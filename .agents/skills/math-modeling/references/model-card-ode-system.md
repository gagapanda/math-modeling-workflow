# 常微分方程初值问题模型卡

## 模型名称与路由信号

常微分方程（ODE）初值问题用于描述有限个连续状态随时间变化，且变化率由当前时间、状态和已声明参数决定的动力系统。当前生产脚本回答确定性一阶 ODE 系统的数值轨迹问题；它不覆盖偏微分方程、边值问题、延迟微分方程、随机微分方程、事件密集的混合系统或参数标定。

## 适用结构

- 状态可表示为有限维向量，且每个状态都有明确初值、单位和来源；
- 每个状态的一阶导数可由当前时间、状态和有限参数显式计算；
- 研究时间区间、输出时间点以及需要检验的守恒量或参考解可提前声明；
- 当前目标是复现给定方程和参数下的初值轨迹，而不是从观测数据反演参数；
- 不存在必须由专用事件处理器描述的大量瞬时切换、冲击或离散控制逻辑。

## 符号与单位

- `t`：时间，单位由输入的 `time.unit` 声明；
- `x_i(t)`：第 `i` 个状态，单位由每个状态单独声明；
- `x_i(t_0)=x_i0`：初始条件，必须与状态单位一致；
- `theta_j`：模型参数，必须记录数值、单位和来源；
- `dx_i/dt=f_i(t,x,theta)`：状态方程，其单位必须等于状态单位除以时间单位；
- `I_k(x,t)`：可选守恒量或不变量，其期望值和绝对容差必须使用同一单位。

当前脚本记录单位但不做符号量纲代数。量纲一致性必须在运行前由建模者独立推导和复核。

## 假设与定义风险

状态边界、正负方向、流入流出符号、时间尺度、初值、参数来源和方程适用范围均正确；系统在所选时间区间内可由当前状态决定，且忽略的空间差异、时滞、随机扰动和离散事件不会改变结论。高影响风险包括把累计量误作瞬时率、混用小时与秒、遗漏源汇项、错误设置边界或初值，以及把拟合参数当作已知物理常数。这些歧义必须进入模型定义寄存器，并在物理机制或结果实质改变时运行替代定义。

## 透明基线

优先使用平衡点、初始导数符号、短时线性近似、守恒总量、单状态指数解或可分离方程解析解作为透明基线。即使主系统只能数值求解，也应至少给出一个极限工况或简化子系统，用来检查方向、数量级和长期行为。求解器成功状态不是基线，也不是模型正确性证据。

## 模型构造

将系统写成 `dx/dt=f(t,x,theta)` 并为每个状态给出一条受限表达式。`scripts/model_baselines/ode_system.py` 使用 `scipy.integrate.solve_ivp`，支持 `RK45`、`RK23`、`DOP853`、`Radau`、`BDF` 和 `LSODA`。表达式经 AST 白名单解析，只允许基本算术和少量单参数数学函数，不使用 `eval`。主求解后自动执行加严容差和减小最大步长两次复算，并在共同输出网格上比较轨迹和端点。

## 输入和参数

JSON 必须声明时间起止、求值点数和时间单位；每个状态的名称、初值、单位和来源；每个参数的名称、数值、单位和来源；每个状态唯一对应的方程、导数单位和来源；求解方法、`rtol`、`atol`、`max_step`；以及数值敏感性阈值。守恒量和闭式参考解为可选项，但只要问题存在可推导的对应证据，就不应省略。参数不能因为“常见”而凭空指定；估计参数时应使用独立的标定与验证流程，当前脚本不负责拟合。

## 验证设计

- **must**：检查状态、参数和方程一一对应，名称唯一，初值、参数、时间和容差有限，单位与来源非空；
- **must**：独立审核每条方程的量纲、流入流出符号、初值和适用时间范围；
- **must**：确认主求解成功、完整到达终点、初值被复现，轨迹和导数均为有限数；
- **must**：加严 `rtol/atol` 并减小 `max_step`，比较完整轨迹与端点，变化必须低于运行前声明的阈值；
- **must**：有守恒律时从方程独立推导并逐时间点复算；有闭式解时逐状态比较绝对和相对误差；
- **should**：检查正性、单调性、平衡点、长期极限和已知上下界，但只对数学上应成立的性质设置门禁；
- **should**：刚性或多时间尺度信号出现时，比较适合刚性问题的方法并报告函数求值、Jacobian 求值和分解次数；
- **not_applicable**：当前确定性前向求解不产生统计置信区间，不验证参数可辨识性，也不支持因果或现实预测主张。

## 敏感性与稳健性

数值敏感性至少包括容差和最大步长；模型敏感性应另行扰动会改变结论的初值、参数、边界、源汇项和时间范围。扰动范围必须来自测量误差、估计不确定性或明确情景。数值稳定只说明离散求解对所选设置不敏感，不能替代参数不确定性、结构不确定性或定义敏感性。

## 失败模式

- 方程量纲不一致，但因为只记录单位而仍能数值运行；
- 初值或参数单位混用，导致轨迹数量级错误；
- 非负状态出现负值，却未检查模型结构、方法或步长；
- 刚性系统使用不合适的方法，计算极慢或产生伪振荡；
- 只比较端点，不检查中间轨迹的相位、峰值或守恒漂移；
- 用同一段错误代码同时生成数值解和“参考解”，形成伪独立验证；
- 把容差稳定性写成参数稳健性或现实预测可靠性；
- 将当前初值脚本用于 PDE、边值、延迟、随机、事件密集系统或参数反演。

## 替代模型与选择证据

离散时刻机制明确时可改用差分方程或状态空间模型；存在空间梯度和边界条件时转向 PDE，复杂 PDE 仍路由 MATLAB PDE Toolbox；已知两端边界而非单端初值时使用边值问题求解器；存在时滞、随机驱动或密集事件时使用相应 DDE、SDE 或混合仿真工具；只有观测数据而机制弱时，应比较回归、时间序列或数据驱动状态空间基线。切换依据是方程结构、数据和验证证据，不是模型名称更复杂。

## 输出证据

生产运行输出 `trajectory.csv`、`solver_sensitivity.csv`、`invariant_check.csv`、`trajectory.png` 和 `run.json`；声明参考解时另输出 `reference_check.csv`。`run.json` 记录输入 SHA-256、运行时版本、方程与单位、求解器统计、敏感性最大变化、守恒残差、参考解误差、初值与有限性检查、输出清单和主张边界。论文使用的峰值、终值、转折时间或守恒结论应从这些文件确定性生成并进入结果对账。

## 下一步动作

先在模型定义寄存器确认状态、初值、参数、单位、方程来源和忽略机制，再构造 JSON 并运行 `scripts/model_baselines/ode_system.py --input <problem.json> --output <new-output-directory>`。人工审阅轨迹图及关键极限，随后对科学参数和结构另做情景敏感性。当前 SciPy 已足够，无需新增依赖；遇到 PDE、边值、延迟、随机、事件密集或参数标定问题时停止使用本脚本并重新路由。
