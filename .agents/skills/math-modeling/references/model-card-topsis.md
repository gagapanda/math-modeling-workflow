# TOPSIS 模型卡

## 模型名称与路由信号

TOPSIS 用于在已确定指标体系和权重后，根据方案到正理想解和负理想解的相对距离进行排序。它不负责发现因果关系、预测未来、自动生成客观权重，也不能替代约束优化。

## 适用结构

- 有多个可比较方案和多个数值指标；
- 每个指标能明确为效益型、成本型或经有依据转换后的其他类型；
- 指标权重来自明确规则、专家判断或独立权重模型；
- 目标是相对排序或优选，而不是求连续决策变量。

## 符号与单位

- `x_ij`：方案 `i` 在指标 `j` 上的原始值，保留原单位；
- `z_ij`：方向统一并标准化后的无量纲值；
- `w_j`：指标权重，`w_j >= 0` 且总和为 1；
- `d_i+`、`d_i-`：到正、负理想解的距离；
- `c_i = d_i- / (d_i+ + d_i-)`：贴近度，无量纲。

## 假设与定义风险

- 指标方向、统计口径和方案边界一致；
- 标准化和距离定义适合指标尺度；
- 指标之间的强相关或重复计量已被审计；
- 权重表达的是题目要求的偏好，而不是从输出排名反向调整。

如果“指标是越大越好还是存在目标区间”“方案集合是否完整”“权重代表客观差异还是决策偏好”会改变排序，应登记到 `problem/model-definition-register.json`。

## 透明基线

先计算方向统一后的等权标准化加权和。TOPSIS 必须至少和该基线比较，检查排名变化是否来自距离结构，而不是数据错误或权重设置。

## 模型构造

1. 审计并统一指标方向；
2. 选择并记录标准化方法；
3. 将标准化矩阵乘以权重；
4. 构造逐指标正、负理想解；
5. 计算到两类理想解的距离和贴近度；
6. 按贴近度降序排序；
7. 从原始数据重新计算关键方案的距离和排名。

## 输入和参数

必须提供：方案标识、指标列、每列方向、权重和标准化方法。常数列必须显式处理；不能让除零、全零范数或无信息指标静默进入结果。

权重不能默认为“客观”。使用熵权、AHP 或业务权重时，必须分别记录其数据来源和解释边界。

## 验证设计

- **must**：检查缺失、非数值、常数列、权重非负且和为 1；
- **must**：从原始数据重算至少一个方案的 `d+`、`d-` 和 `c`；
- **must**：扰动关键权重并报告前列方案的秩变化；
- **must**：比较至少一种合理标准化方法或解释为何不适用；
- **should**：与等权加权和基线比较；
- **should**：检查高度相关指标导致的重复计量；
- **optional**：在方案或指标存在测量误差时做区间或 Monte Carlo 稳健性分析。

## 敏感性与稳健性

重点扰动权重、正负向定义、标准化方法以及接近的方案数据。报告“排名是否稳定”和“哪些假设会改变优选结论”，不能只报告贴近度小数。

## 失败模式

- 用 TOPSIS 代替权重论证；
- 成本型指标方向处理错误；
- 常数列被赋予虚假区分度；
- 指标高度重复造成双重计权；
- 只给最终排名，没有距离、权重和敏感性证据；
- 把相对排序解释为绝对优劣或因果结论。

## 替代模型与选择证据

- 只需要透明综合分数：加权和可能更合适；
- 需要专家成对判断：考虑 AHP，并检查一致性；
- 需要数据离散度权重：熵权可作为权重来源，但仍需解释业务含义；
- 目标是降维而不是偏好排序：考虑 PCA；
- 有决策变量和约束：使用优化模型，而不是 TOPSIS。

## 输出证据

至少生成：输入摘要、方向和权重表、标准化矩阵、正负理想解、距离、贴近度、排名、敏感性结果和与基线的差异。论文中的排名和数值必须从同一权威结果文件取得。

## 下一步动作

数据审计完成后，可将 TOPSIS 脚本作为 workflow Python step 接入；在生产接入前，脚本必须通过输入边界、数值性质、排名稳定性和原始数据只读测试。
