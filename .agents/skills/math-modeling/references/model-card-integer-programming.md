# 整数与混合整数规划模型卡

## 模型名称与路由信号

整数规划用于数量、选择、启用、分配、排产、选址等不可分割决策；混合整数规划同时容纳离散变量和连续变量。它回答已明确目标、约束和变量域下的最优或当前最好可行方案，不能替代业务口径审查，也不能仅凭求解器返回证明模型定义正确。

## 适用结构

- 目标函数是决策变量的线性组合；
- 约束可写成线性小于等于、大于等于或等式；
- 至少一个变量必须取整数或二元值，其余变量可连续；
- 每个变量都有明确名称、单位、上下界和离散含义；
- 所有目标系数、约束系数和右端项均可追溯。

若目标或约束含变量乘积、幂、分段非线性，必须先证明其线性化等价且边界有效，否则应转向非线性、约束规划或专用模型。

## 符号与单位

- x_j：第 j 个决策变量，可为连续、整数或二元变量，单位由业务定义；
- c_j：变量 j 的单位目标贡献，单位为目标单位除以变量单位；
- a_ij：变量 j 对约束 i 的资源消耗或贡献；
- b_i：约束 i 的容量、需求或平衡值；
- c 转置乘 x：原始目标值，必须保留利润、成本、距离等业务单位；
- z_LP：连续松弛目标，是整数问题的界，不是可直接执行的方案。

## 假设与定义风险

离散粒度、时间窗、库存结转、互斥与联动逻辑、容量、需求、成本、收益和边界都必须与题意一致。必须登记到模型定义寄存器的高影响歧义包括：是否允许拆分、二元变量代表启用还是选择、产销口径、期初期末边界、轮作或覆盖规则、超量处理方式，以及大 M 线性化中的逻辑含义和 M 的依据。

大 M 过小会错误删除可行解，过大会削弱连续松弛并引起数值问题。M 必须从有效变量边界推导，并做扰动或替代形式核验，不能凭经验随意填写。

## 透明基线

输入应提供一个人工可行方案 baseline_solution，例如现行排程、全不选方案或简单贪心方案。脚本先复算其约束、边界和整数性，再比较优化目标。若全零并不满足需求或覆盖约束，就不能把它冒充基线。没有人工可行基线时，至少应报告一个可解释的构造过程和失败原因。

连续 LP 松弛是另一项必备参照：最大化问题中它给出上界，最小化问题中给出下界。它用于衡量离散性代价和模型强度，但不是整数可行基线。

## 模型构造

求解最小化或最大化 c 转置乘 x，满足线性约束、变量边界与整数域。最大化在求解器内部转换为最小化，最终目标值仍用原始系数重新计算。生产脚本使用 scipy.optimize.milp 的 HiGHS 后端，并另外求解同一模型的连续 LP 松弛。

状态必须分开解释：

- optimal：存在复算可行的候选解，且求解器已证明当前容差下最优；
- feasible_limit_reached：时间或节点限制前找到了复算可行的 incumbent，但没有证明全局最优；
- limit_reached_without_feasible_candidate：达到限制且没有可用可行解；
- infeasible：模型被判定不可行；
- unbounded：目标无界；
- other_failure：其他求解或数值失败。

只有 optimal 可以表述为已证明最优。feasible_limit_reached 只能称为当前可行方案，并同时披露限制、MIP gap 和对偶界。

## 输入和参数

JSON 必须声明目标方向、变量列表、目标系数和约束。变量类型仅允许 continuous、integer、binary；二元变量由脚本强制限制在 0 到 1。变量与约束名称必须唯一，系数维度一致且为有限数，上下界合法。单位字段应覆盖变量、目标和约束。

可选 baseline_solution 必须与变量维度一致并通过独立复算。time_limit 和 mip_rel_gap 是求解资源与停止容差，不是模型参数；必须按运行记录披露，不能把更宽松容差包装成相同强度的最优性证明。

## 验证设计

- must：验证名称、维度、有限性、边界、变量类型和二元变量域；
- must：将候选解代回全部原始约束和变量边界；
- must：逐个整数或二元变量复算其到最近整数的偏差；
- must：用原始目标系数重新计算目标值；
- must：区分求解状态、候选解是否存在、候选解是否可行和是否已证明最优；
- must：记录 MIP gap、对偶界、节点数和停止限制；
- must：求解 LP 松弛并记录其目标界；LP 松弛可行性检查不得要求整数性；
- must：有人工基线时先验证其约束、边界和整数性，再报告目标改善；
- should：从业务数据重算入选方案的成本、收益、数量或排程汇总；
- should：对关键容量、需求、收益、成本、大 M 和时间限制做敏感性分析；
- not_applicable：单次确定性 MILP 不提供概率置信区间或因果结论。

不得把 LP 松弛解逐项四舍五入后当作整数方案。四舍五入可能同时破坏容量、覆盖、互斥、平衡和联动约束；任何启发式修复后的方案都必须重新通过全部可行性检查。

## 敏感性与稳健性

优先扰动会改变可行域或结论的参数：容量、需求、预算、上下界、收益、成本、时间窗和大 M。记录最优选择、目标、可行性、求解时间及 MIP gap 是否变化。大型问题还应比较不同时间限制和 mip_rel_gap，明确更多计算是否实质改善 incumbent 或缩小最优性缺口。

LP 松弛与整数目标的差距较大时，应检查模型表述是否过弱，并考虑更紧边界、有效不等式或等价的强化形式。该差距是诊断信息，不自动证明求解器或模型错误。

## 失败模式

- 把时间限制下的可行 incumbent 写成全局最优；
- 只引用 success 或状态码，不复算原始约束、边界和整数性；
- 将连续 LP 解四舍五入后直接使用；
- 漏掉启用变量与连续数量之间的联动约束；
- 使用无依据的超大 M，导致松弛过弱或数值不稳定；
- 模型不可行时删除约束，却不解释业务定义变化；
- 变量缺少上界而使目标无界或大 M 无法推导；
- 忽略单位，使面积、产量、金额和比例系数错位；
- 将求解器最优等同于业务模型正确。

## 替代模型与选择证据

全部变量可分割时用连续线性规划，并比较其解是否具有业务可执行性。非线性不能等价线性化时用非线性优化；复杂逻辑和排程可比较约束规划；路径、匹配、流量等具有专用结构时优先使用成熟图算法或网络流模型；参数不确定且会改变决策时比较情景、稳健或随机规划。

模型切换的证据应来自变量域、约束结构、LP 松弛强度、规模、求解状态和验证结果，不能只比较求解器名称或目标值。

## 输出证据

integer_programming.py 生成 solution.csv、constraint_check.csv、lp_relaxation.csv 和 run.json。run.json 绑定输入 SHA-256，并记录变量与约束规模、求解器状态、solution_class、候选解可用性、proven_optimal、原目标值、约束/边界/整数最大违反量、MIP gap、对偶界、节点数、LP 松弛目标，以及人工基线可行性和目标改善。

论文或报告还应给出有单位的决策汇总、关键活动约束、未收敛时的资源限制与最优性缺口，以及从原始业务数据独立重算的核心指标。
