# 数据审计契约

## 目的

数据审计位于问题契约与模型路由之间。它描述输入事实、暴露需要处理或解释的数据风险，并为后续清洗与建模决策提供哈希绑定证据。审计不是自动清洗器，也不能仅凭统计异常删除记录、填补缺失或断言目标泄漏。

## 使用顺序

1. 保留原始文件，确认每行的观测单位和每列的业务含义、单位及来源；
2. 显式声明 ID、目标、时间和分组列，未声明列仅作为候选特征审计；
3. 运行 `scripts/data_audit.py`，先处理 blocker，再逐项审阅 warning 和 review；
4. 对受支持的机械变更，按 `data-cleaning.md` 创建哈希绑定的版本 1 清洗计划；复杂聚合或领域变换另写确定性代码并保留同等级证据；
5. 用 `scripts/data_clean.py` 将处理后数据写到新路径，保留变化账本，再重新审计并比较输入、输出哈希和行列变化；
6. 数据角色与样本边界稳定后再进入模型路由和验证切分。

## CLI

```powershell
python scripts/data_audit.py `
  --input <source.csv> --output <audit-directory> `
  --id-columns <id-or-composite-key> `
  --target-columns <targets> `
  --time-columns <timestamps> `
  --group-columns <independent-group-boundaries>
```

角色参数均可省略，但缺少角色声明会限制泄漏、唯一性和时间顺序检查的含义。多个 ID 列组成联合键；多个分组列定义时间顺序检查的联合分组边界。

## 压缩容器—成员双层血缘

若原始输入来自 ZIP、RAR 或 7z，不得只登记外层压缩包或临时解压文件之一。对每个实际进入代码、清洗或人工转录的成员，至少登记：

- `container_path`：保存的原始压缩容器路径；
- `container_sha256`：容器字节的 SHA-256；
- `member_path`：成员在容器内的规范相对路径；
- `member_sha256`：实际解压成员字节的 SHA-256；
- `extraction_method` 与 `extracted_at`：使用的工具/命令和带时区时间；
- `working_copy_path`：案例内实际使用的只读或工作副本路径。

容器哈希证明收到的是哪个压缩包，成员哈希证明模型实际读取的是哪个文件；两者不可互换。重新下载、重新解压、改用另一个解压器或移动到新工作副本后，必须重新核对成员路径与成员哈希。禁止用容器哈希填写成员哈希、只保留系统临时目录路径，或在成员不一致时继续建模。现有 `data_audit.py` 的 `input_sha256` 只绑定传入的单个 CSV；压缩来源的双层血缘应在案例数据血缘记录中另行保存，不能从该字段反推。

## 输出证据

- `columns.csv`：字段角色、读取类型、语义类型、缺失、唯一性和数值可转换率；
- `numeric_summary.csv`：有限值计数、均值、标准差、分位数、极值、零值和负值；
- `categorical_summary.csv`：低基数类别的前 20 个频数；
- `outliers.csv`：按声明 IQR 倍数计算的异常候选摘要；
- `correlations.csv`：数值列两两完整观测上的 Pearson 相关；
- `time_summary.csv`：日期时间或数值时间类型、原单位范围、解析失败和输入顺序下降次数；
- `duplicate_rows.csv`：重复行位置、内容哈希和声明 ID；
- `issues.csv`：稳定代码、严重度、范围、数量、事实描述和下一步动作；
- `run.json`：输入 SHA-256、角色、参数、问题计数、输出清单和解释边界；
- `summary.md`：供人快速阅读的执行摘要。

## 严重度

- `blocker`：声明 ID/目标/时间缺失、联合 ID 不唯一、目标常数、非有限数值、目标精确副本候选或时间解析失败。模型运行前必须解释或修复；
- `warning`：较高缺失率、目标近乎完美数值相关候选、时间顺序下降等可能改变验证设计的问题；
- `review`：少量缺失、完整重复行、IQR 异常候选和高相关特征等需要结合来源判断的问题；
- `info`：保留给不影响建模就绪状态的事实性提示。

`ready_for_modeling=true` 只表示当前声明和机械规则下没有 blocker，不表示数据真实、充分、无偏、无泄漏或适合任何具体模型。

## 解释边界

- IQR 围栏只定位异常候选；极端值可能是重要事件、真实边界或录入错误；
- 高相关可能来自定义关系、单位换算、共同原因或泄漏，必须检查字段生成时间和来源；
- 目标精确副本是强风险，但仍需确认字段语义；近乎完美相关只标 warning，不直接判定泄漏；
- Pearson 只描述线性关联，不覆盖非线性依赖、类别关联、时间泄漏或组泄漏；
- 审计不推断单位、不检查外部业务规则，也不替代训练/测试隔离和模型特定验证；
- 任何清洗必须保留原始输入，并记录行列变化、规则、理由和可能的信息损失；受支持的 CSV 机械变更遵循 `data-cleaning.md`。
