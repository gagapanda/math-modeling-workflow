# 连续非线性优化模型卡

## 模型名称与路由信号

连续非线性优化用于目标或约束含乘积、幂、指数、对数等非线性关系的有界单目标决策。它寻找多个声明起点中的最佳可行局部解，不能自动证明全局最优，也不处理整数变量、多目标 Pareto 集或随机参数。

## 适用结构

- 决策变量连续，且每个变量都有有限上下界；
- 目标是一个可数值求值的标量表达式；
- 约束可写成非线性 `<=`、`>=` 或 `=`；
- 参数、边界、单位和来源可明确登记；
- 函数在可行域附近足够平滑，有限差分和 SLSQP 有合理数值条件。

## 符号与单位

- `x_j`：连续决策变量，必须声明单位与有限边界；
- `f(x)`：最小化或最大化目标，保留成本、效益或物理量单位；
- `g_i(x)<=b_i`、`g_i(x)>=b_i`：不等式约束；
- `h_k(x)=b_k`：等式约束；
- `epsilon_f`：可行性容差，只是数值判据，不是业务容差。

## 假设与定义风险

表达式、约束方向、参数口径和变量边界准确；目标和约束在搜索区间内可求值。最重要的风险通常是漏约束、量纲不一致、把离散决策连续化、在奇点附近求值，以及未经证明就宣称全局最优。目标、约束、边界或聚合口径的替代定义必须进入模型定义寄存器。

## 透明基线

JSON 可提供现行方案或手工可行方案 `baseline_solution`。脚本先复算其目标、边界和约束，再比较最佳局部候选相对基线的目标改善。没有可行基线时，应至少提供手算边界、网格小样本或线性化方案作为独立对照。

## 模型构造

生产基线用受限算术表达式描述目标与约束，仅允许变量、有限常数、基本运算及 `abs/cos/exp/log/sin/sqrt/tanh` 单参数函数。它以声明初值、边界中点和固定种子均匀起点运行多次 SciPy SLSQP，筛选求解器成功且重新代入后可行的候选，再按原始目标方向选最优者。

## 输入和参数

JSON 必须包含连续变量的名称、有限上下界、单位和来源，以及目标表达式、单位和来源。每条约束必须有唯一名称、表达式、方向、右端值、单位和来源。`solver` 声明 `starts`、`seed`、`maxiter`、`ftol`、可行性容差和目标一致性容差。可选 `initial_solution`、`baseline_solution` 和带来源的 `analytical_reference`。

## 验证设计

- **must**：拒绝任意调用、属性访问、未知变量、非有限边界、整数变量和多目标输入；
- **must**：将候选代回原始约束和边界，报告最大违反量；
- **must**：只从“求解器成功且复算可行”的候选中选择；
- **must**：记录每个起点、退出状态、目标、解和违反量；
- **must**：明确输出只代表多起点中最佳局部候选；
- **should**：提供人工可行基线、解析参考或独立网格/符号推导；
- **should**：高影响问题独立核对梯度、KKT 条件和尺度；
- **not_applicable**：本基线不提供全局最优界、MIP gap、整数可行性或 Pareto 前沿。

## 敏感性与稳健性

检查起点数量和种子、变量尺度、边界、关键约束右端项、参数和求解容差。不同起点的目标极差及近优起点数用于暴露局部最优风险，但一致收敛仍不是全局证明。结论若依赖边界附近的小差异，应报告参数扰动后的方案和目标变化。

## 失败模式

- 在非凸问题上单次运行后报告“全局最优”；
- 接受 `result.success` 却不复算约束；
- 变量尺度跨越多个数量级，导致有限差分和停止判据失真；
- `log`、`sqrt` 或除法在搜索域内遇到非法值；
- 用连续值替代必须为整数、二元或组合的决策；
- 人工基线不可行却仍计算改善；
- 将数值容差解释成现实系统允许的违反量。

## 替代模型与选择证据

全部线性时使用线性规划；存在整数或二元决策时使用混合整数规划；需要可证全局最优时采用凸性证明、全局优化器或问题特定界；多个不可公度目标时构造 Pareto 分析；随机参数显著时做情景、稳健或随机优化。切换依据来自数学结构和需要证明的主张。

## 输出证据

`nonlinear_optimization.py` 生成 `solution.csv`、`constraint_check.csv`、`multistart.csv` 和 `run.json`。证据包含输入 SHA-256、表达式与来源、固定种子、全部起点状态、最佳目标、约束/边界复算、基线改善、起点一致性、解析参考误差和全局最优警告。

## 下一步动作

先用有单位、有来源的 JSON 明确有限搜索域和一个人工可行方案。运行 `scripts/model_baselines/nonlinear_optimization.py` 后，只有候选复算可行、多起点证据稳定且关键参数敏感性可接受时，才把它作为局部优化方案写入结论。现有 SciPy 足够，无需安装新依赖。
