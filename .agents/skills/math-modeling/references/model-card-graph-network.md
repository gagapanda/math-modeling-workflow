# 图与网络模型卡

## 模型名称与路由信号

图与网络模型用于节点和边构成的路线、连接、运输或容量结构。当前生产脚本回答单源单汇最短路与最大流问题；它不能直接回答车辆路径、时间窗、多商品流、动态网络、匹配、选址或网络因果问题。

## 适用结构

- 对象可明确表示为名称唯一的节点和端点明确的边；
- 最短路中每条边有有限、非负、同口径的费用或距离；
- 最大流中每条有向边有非负整数容量，并且流量可分割；
- 源点、汇点、方向性和边参数来自题意、附件或明确假设；
- 当前任务是单源单汇静态网络，不含随时间变化的边或路径耦合约束。

## 符号与单位

- `G=(V,E)`：由节点集 `V` 与边集 `E` 构成的图；
- `c_ij`：最短路中边 `(i,j)` 的费用、距离或时间，单位必须统一；
- `u_ij`：最大流中边 `(i,j)` 的容量，单位如 `vehicles/hour`；
- `s,t`：源点与汇点；
- `d(s,t)`：从 `s` 到 `t` 的最短路总成本；
- `f_ij`：边流量，与容量同单位；`F` 为源到汇的总流量。

## 假设与定义风险

边方向、费用、容量和节点身份准确；最短路费用可相加且非负；最大流满足单商品、静态、可分割和中间节点守恒。高影响风险包括把双向道路误写为单向、把通行时间与距离混加、忽略容量时间尺度、把共享资源重复计入多条边，以及漏掉转向、时间窗或路径依赖约束。这些歧义必须进入模型定义寄存器。

## 透明基线

最短路可用直接可见路线或简单贪心路线作为人工基线，并从原始边表复算成本。最大流可先计算源点出边容量和汇点入边容量的较小者作为上界，再给出一组手工可行流作为下界。当前脚本输出最小割容量，为最大流提供独立的等值证据。

## 模型构造

最短路最小化所选连续边的总费用并保持从源到汇的路径连续性，使用 `scipy.sparse.csgraph.dijkstra`。最大流最大化源点净流出，满足 `0<=f_ij<=u_ij` 和所有中间节点流守恒，使用 `scipy.sparse.csgraph.maximum_flow(method=dinic)`。求解后由独立代码按原始边表重建路径或流量证据。

## 输入和参数

JSON 必须声明 `task`、`directed`、唯一节点列表、不同的 `source`/`target`、参数单位、`source_note` 和非空边表。最短路边使用 `cost`；最大流边使用整数 `capacity`。当前接口拒绝重复边、自环、未声明端点、负费用、负容量、浮点容量以及无向最大流；无向容量应按业务含义显式展开为两条有向边。

## 验证设计

- **must**：检查节点与边端点、方向、重复边、自环、单位、参数有限性和任务字段；
- **must**：最短路从原始边表逐步检查路径连续性并重新求和，结果必须与求解器距离一致；
- **must**：不可达汇点必须失败，不能输出空路径冒充结果；
- **must**：最大流逐边检查非负与容量上界，逐节点复算流守恒，源点净流出和汇点净流入必须等于总流量；
- **must**：从残量网络独立求源侧节点，重新计算割容量，并检查最大流等于最小割；
- **should**：用手工路线、源汇容量上界、不同后端或小规模枚举复核关键结果；
- **not_applicable**：确定性最短路和最大流不提供统计置信区间、随机种子稳定性或因果结论。

## 敏感性与稳健性

对会改变路线或瓶颈的关键边做删除、方向替换和费用/容量扰动，记录最短路结构、总成本、最大流量和最小割组成是否变化。并列最短路应报告替代路径；接近饱和的割边应作为重点风险。扰动幅度必须来自测量误差、工况或题目情景，不能机械套用百分比。

## 失败模式

- 把地理相邻当作实际连通，或漏掉单行、禁行、换乘和时间窗；
- 混合公里、分钟、费用等不可直接相加的边权；
- 用 Dijkstra 处理负费用，或把负费用静默截为零；
- 最大流容量时间尺度不一致，或把双向共享容量错误复制为两份独立容量；
- 只报告路径节点或总流量，不列边级证据和复算；
- 把最大流当作实际调度方案，忽略离散车辆、路径组合和动态拥堵；
- 把当前脚本扩展到多商品流或车辆路径而不重新建立优化模型。

## 替代模型与选择证据

存在负边权且无负环时改用 Bellman-Ford；需要所有点对距离时使用 Floyd-Warshall 或多源算法；需要最小生成树、匹配、最小费用流、车辆路径、时间窗或多商品流时使用对应图算法、LP/MILP 或专用求解器。切换依据是边语义和约束结构，不是网络规模或算法名称。

## 输出证据

最短路输出 `path_edges.csv` 和 `run.json`，记录路径节点、逐边费用、累计费用、求解器距离与独立重算值。最大流输出 `edge_flows.csv`、`node_balance.csv`、`minimum_cut.csv` 和 `run.json`，记录逐边容量/流量、节点守恒、源汇平衡、残量源侧、割容量及最大流最小割检查。所有任务记录输入 SHA-256、运行版本、单位、来源说明和主张边界。

## 下一步动作

先从附件或题意形成可审阅的节点表和边表，在模型定义寄存器确认方向、费用/容量口径和时间尺度，再运行 `scripts/model_baselines/graph_network.py`。正文必须展示关键路径或瓶颈割及其业务含义；若出现时间窗、车辆整数性、路径耦合或多商品竞争，应切换到相应 LP/MILP，而不是修改输出解释。现有 SciPy 足够，无需为当前基线安装 `networkx`。
