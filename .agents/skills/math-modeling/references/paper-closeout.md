# 论文提交前收口

本卡只补足既有论文质量门，不建立第二套提交状态机。目标是让评委从正文读懂论证，同时保证被审核、被打包、被提交的是同一版本。机器通过不等于论文优秀、引用真实、AI披露完整、人工接受或官方提交。

## 顺序与责任

1. **先清正文，再冻结页面。** 删去阶段号、写回过程、旧视觉记录等内部操作叙述；移至工作区QA记录。保留假设、失败结果、局限、引用、真实AI披露、匿名的运行方法。不能把未运行写成已运行。不得为了缩短篇幅删除核心推导或符号说明。
2. **按题逐问做评委重建。** 不打开源码，写出问题对象、定义与单位、推导、候选/基线、选择理由、求解步骤、结果解读、验证及边界，并记录正文位置、能重建的链和缺口。关键词、节标题、图数、页数都不能代替该阅读。旧审查只有在论证正文未变且有逐段差异证据时才能承接；不能只更换哈希和审查日期。
3. **核验引用、披露、匿名。** 引用逐条核对来源作者/题名/年份与正文使用位置，修正缺失、错配与不相关条目。有参考文献标题不算通过。AI详情必须来自实际日志，核对工具、使用内容、范围和正文声明；旧详情PDF存在不证明覆盖本版。匿名同时查正文、附录、DOCX核心属性/批注/PDF属性及支撑包内容；竞赛全称中的“大学”、代码`@`不是身份信息，不能整类忽略真实学校/姓名。每项排除有上下文依据。
4. **构建最终文件再审页。** 保存最终MD/TeX、DOCX、PDF和页图哈希；逐页实际查看可读尺寸的图像。缩略图/拼接图只能做导航；发现变化的页必须重新看。未变页承接须绑定旧审查及完全一致的页图。完整源码中的正则和`##`可是真实代码字面量；保留原始扫描错误与逐项范围证据，不能直接覆写原检查为PASS。
5. **归档后验证实际ZIP。** 先完成论文终审，后按既有`package_submission.py`允许清单打包，再用`audit_support_package.py`在隔离解压目录运行声明的入口。不得在终审前依赖包含该终审报告的最终ZIP，避免循环依赖。清单/报告若入包，应先定稿；入包后改源报告会使包失效。验证包内每项路径、内容哈希与字节数，禁止额外项、重名项、路径逃逸。外部清单绑定ZIP哈希，不做自哈希。任一字节变化，重新打包、核验并作废依赖旧包的M7预检。
6. **按当届规则验收。** 大小上限、正文范围、是否单独提交AI详情、匿名范围、命名等读取当前已核验官方快照，不把本次练习的页数或20 MiB测试阈值硬编码成通用规则。无法取到权威来源时标记未核验，不填虚假的核验日期。现有M6、M7及F2人工与上传要求保持不变。

## 默认启用与兼容

`scaffold_case.py`的新practice/submission案例包含`paper/closeout-review.json`（pending）及`case.json`中的`paper_closeout_required=true`。`finalize_case.py`自动检查该文件，pending、缺失、失效哈希会阻止`ready_for_submission`；不需要新增workflow步骤。旧案例未声明时只保留兼容路径，报告`not_run_or_not_required`，不得称收口通过。旧案例主动采用时复制模板，改完审核内容后由finalizer执行；不要批量重写历史论文。explore不强制终稿门。

审查证据应保存为独立、已定稿的文件，不绑定finalizer将自动改写的QA登记表或终审报告。finalizer写出报告后再次核验收口记录及证据，记录被替换或证据变化均撤销通过状态。

审核表的`artifacts`绑定实际源码、DOCX和PDF；四类`reviews`各自填写`reviewed`、具体发现与局限，以及实际阅读的证据路径/哈希。评委重建记录逐问给出正文位置和重建链；引用记录逐项对应文献/使用点/来源；AI记录核对本版实际使用覆盖及缺口；匿名记录区分真实身份与误报，覆盖元数据和支撑材料。至少30字符只是防空检查，绝不是内容质量评分。发现未闭环缺口应保持pending。审核者写真实AI/人工身份，AI不签人工M6/M7。

```powershell
python scripts/audit_paper_closeout.py --case-dir <case> --json
```

该脚本只读，校验源文件中的已知内部措辞和四类审查证据的新鲜度；不判定来源是否真的读过、数学是否正确或人工是否真的审核。正式终审仍要求结果对账、质量门、逐页视觉、规则与AI审计全部通过。

## ZIP独立一致性复核

已有打包器仍为主入口。对于额外支撑快照可独立执行：

```powershell
python scripts/audit_paper_closeout.py --case-dir <case> --package <support.zip> --manifest <external-inventory.json> --json
```

外部清单格式为`schema_version: 1`、`package_sha256`、非空`files`数组；每项包含包内`path`、可选的案例相对源路径`source`（默认与path相同）、`bytes`、`sha256`。清单必须从声明的最终源文件建立，而非只读取包内字节后自我证明。验证器逐项核对源文件与ZIP解压流，不执行代码。它不证明匿名、规则大小、依赖完整或模型可重放；这些仍由既有打包/M6/烟雾门检查。

## 必须拦截的回归

- 空审查、章节存在或旧详情PDF被当成完整披露；
- 审查后改PDF、改源码、改引用/AI证据，仅改日期想沿用PASS；
- 只看拼接图却登记所有页已完整阅读；
- 只扫描正文漏掉元数据，或忽略整个“大学”类别；
- ZIP缺清单、额外文件、重复成员、错误字节数、内容被替换；
- 修改已入包报告而不重建包；
- 模板审查pending被删掉后绕过新案例finalizer；
- 因内部措辞清理而删掉真实研究局限或源码字面量。

## 表达修订的验收边界（2025 E 修订增量）

评委重建证据除记录推导、选模和结果位置，还应逐项核对：摘要/技术路线/正文是否描述同一统计通路；配对集与对象层相关集是否各有分母；符号表的单位、集合/映射类型和首次定义位置是否正确；“预先声明”是否有时间证据；连续情景与离散观测是否区分。未实际执行的参数扰动只能记作未量化的边界审查。机理、优化等题型按对象裁剪，不能强套配对统计。

`source_hygiene` 新增拦截“套用其他题型模板”和“人为补入回归性能比较/训练采纳规则”等内部话术，仅扫描代码围栏外叙述。它不判断候选集是否预注册、公式是否正确或统计单位是否一致；这些必须保留实质性审查证据。不得把本次英文图标签、附录总页数、尾页留白或未经可读尺寸逐页复核的旧结论当作通用模板标准。最终绘图脚本修改后须核对嵌入图字节确由新脚本生成，不能只同步源码而沿用旧图。

## 全文接入检查（Markdown / Word）

新 practice/submission 案例另带待填写的 `paper/chapter-integration.md`、`paper/integration-plan.json`，及 `paper_integration_required=true`。前者是内部评委重建工作表，不并入正式论文；完成逐问阅读后，将实际记录绑定到原有 `reviews.reviewer_reconstruction.evidence`。不是只检查“写了多少段”：必须从正文恢复必要推导、实际代入、同口径比较和选择判断；不能恢复就改正文或收窄主张。

后者采用模板的精确字段，初始 pending；由作者核对后才设 reviewed，并用 `closeout-review.json.integration.plan` 绑定其路径与 SHA-256。收口门与 finalizer 自动运行本检查，并沿用最终报告写出后的二次绑定校验。缺计划、待完成、哈希过期、衔接不一致均阻止通过。旧案例无启用声明且没有 integration 记录时报告 `not_run_legacy`（passed=null），不冒称检查过。

- 正文边界填 Markdown 中不含井号的精确源码附录标题及 Word 的对应可见标题；它们须各唯一。无源码附录可同时留空。每一附录代码围栏须映射到案例内真实文件及精确小标题，逐字比对（仅统一换行及首尾空行），不得遗漏或重复映射。
- 编号策略 consecutive 要求已编号公式从1连续；explicit 允许章节编号或特定标签，但仍禁止重复及悬空引用。数量由本论文提取，既不要求所有公式编号，也不沿用历史案例数量。
- 支持独占行 `$$` 或 `\[...\]` 显示公式、`\tag{...}` 可见标签、字面“式（n）/Eq(n)”引用。原生 Word 显示数学须为 OMML 段落或带可见编号的独立数学对象。不把显示公式个数/编号匹配说成公式内容或行内数学逐项等价证明。符号引用 `\ref`、TeX equation/align 环境不支持，需另用经审查适配路线。
- 图像仅支持行内、本地、案例内路径的 Markdown 图片；按正文绘图实际引用的媒体字节核对，DOCX ZIP 里藏着未用新图不能蒙混通过。转换格式或重编码图像需明确的经验证适配，不能为过门替换源文件或随意忽略图片。
- 非空 support_manifest 指向含 files 数组的清单，每项 path/bytes/sha256；验证当前源文件，源码附录映射必须在清单内。空值明确表示未请求此子检查，不代表支撑包合格；实际 ZIP 与运行烟雾检查仍走既有门。

独立诊断命令（从 Skill 根调用；正式收口不必重复手工串联）：

```powershell
python scripts/audit_paper_integration.py --case-dir <case>
```

该门只读、标准库实现，不启动 Word、不安装绘图依赖，也不执行课程代码。行内公式、符号语义、图文对应关系与 PDF 全页可读性仍须人工/AI实际阅读并记录；pending 模板或机器 PASS 不能充当这种审查。原生 TeX 沿用既有适配与页审路线，本门不能声称兼容；新案例改路线需明确审查替代验收方案，不得静默删 required 标记。
