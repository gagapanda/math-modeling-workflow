# 论文证据故事板

> 用途：在正式起草一问之前，把**直接答案、公式、数据/假设、模型、数字、图表、验证和结论边界**放进同一条可回溯链。它是写作前的证据组织接口，不是固定页数、公式数或图表数配额，也不能代替模型、结果、视觉或合规质量门。

## 1. 何时使用

在已经完成题目拆解、数据审计和至少一轮可复算结果之后，针对每个实质性小问填写一张故事板；共享模型可以复用核心定义，但每问仍要写清自己改变的输入、约束、结果和验证。

不要在下列情形用故事板虚构完整性：

- 结果尚未运行、未登记或仍会改变；
- 公式没有连接到实际实现或可检查输出；
- 图表尚无可回溯数据来源；
- 验证设计与最终主张不匹配；
- 当前仅能给出探索性发现，而不是正式答案。

结果冻结后，故事板中的结论性数字、图表主张和边界必须与冻结结果登记一致；发生数值、模型、图或验证变更时，先更新故事板，再修改正文。

## 2. 每问必须锁定的十项

| 字段 | 必须写清的内容 | 证据落点 |
|---|---|---|
| 问题与直接答案 | 对题设交付物的答案、单位、条件、状态（候选/已验证/不可确定） | 结果登记、结论草稿 |
| 定义/符号入口 | 全局符号表的位置；局部新增符号的含义、单位/域、索引或信息时点 | 符号说明、模型段 |
| 核心公式/机制 | 方程、约束、损失或更新规则；现实关系与可检查输出 | 模型定义、实现、单元/守恒/量纲检查 |
| 数据/假设证据 | 原始来源、清洗版本、参数来源、关键假设及其影响 | 数据血缘、清洗日志、假设登记 |
| 基线与主模型 | 可解释基线、主模型增加的结构、比较口径和选择理由 | 候选比较、结果登记 |
| 结果证据 | 结论数字、单位、计算版本和结果 ID/生成文件 | 冻结结果登记、表格生成物 |
| 图/表主张 | 每图/表仅一个主要主张；范围、单位、比较口径与不能支持的强结论 | 图表登记、图注、数据文件 |
| 验证 | 与主张匹配的验证方法、数值、失败结构或异质性 | 验证记录、诊断图/表 |
| 边界与禁止推出 | 不得推出的因果、全局最优、训练保证、无条件外推或置信结论 | 局限段、结论审计 |
| 正文/附录分工 | 正文中独立理解所需的链；代码、长表、全量诊断和审计证据放置处 | 论文结构、支撑材料清单 |

**独立符号说明是正式论文的硬要求**：全局反复使用的输入、状态、决策变量、参数、指标和索引必须在实质性模型前的“符号与单位”表中统一定义；只用一次的局部中间量在首次出现处定义，避免符号表失控膨胀。

## 3. 填写顺序与最低可交付物

先填写可改变结论的字段，而不是从背景或版式开始：

```text
直接答案
→ 符号/单位与定义边界
→ 核心公式或机制
→ 结果来源
→ 匹配验证
→ 禁止推出
→ 基线比较
→ 最关键图/表
→ 正文/附录分工
```

时间不足时，保留前六项；再保留一项透明基线比较和一张最能改变判断的图/表。优先删除重复图表、长背景、装饰流程图、非关键中间推导和版式润色，**不得**删除直接答案、符号/单位、核心方程、结果来源、验证、限制、匿名/AI/提交检查。

## 4. 最小故事板模板

```text
Q__｜直接答案：________________（单位/条件/结果状态：____________）

1. 定义/符号入口
- 全局符号表：________；本问新增：________（单位/域/索引/信息时点：________）。

2. 核心公式/机制
- 公式/方程 ID：________；现实关系：________；可检查输出：________。

3. 数据/假设证据
- 数据/版本：________；参数/假设来源：________；采用原因与影响：________。

4. 基线与主模型
- 透明基线：________；主模型增加：________；同口径比较/选择理由：________。

5. 结果与图表
- 结果 ID/生成物：________；关键数字：________（单位：________）。
- 图/表：________；唯一主要主张：________；范围/比较口径：________；不能支持：________。

6. 验证与边界
- 验证：________ 对应主张 ________；结果/失败结构：________。
- 适用边界与禁止推出：________。

7. 正文/附录分工
- 正文保留：________；附录/支撑材料保留：________。
```

## 5. 三类常见适配

### 5.1 机理、几何或动态题

核心链优先写清：现实对象 → 坐标/时间与局部符号 → 几何或物理映射 → 状态闭合 → 事件/约束逻辑 → 数值更新顺序 → 结果。验证应对应守恒、量纲、步长/网格、初始状态、定义敏感性或可行性；有限搜索只能产生条件候选，不能自动称为全局最优。

### 5.2 约束优化、多目标或鲁棒决策题

锁定决策变量、目标、每条约束、求解状态、候选可行性和比较口径。图表可以说明候选比较、活跃约束、权衡或压力测试，但有限候选集、迭代上限和离散场景不构成连续 Pareto 前沿、全局最优或生产认证。

### 5.3 统计预测、重复测量或条件情景题

先锁定部署对象与数据层级；预处理、特征选择和拟合都必须在验证折内进行。随机行级切分不得支持新个体、新设备或新场地外推；报告总体误差时还要登记组别失败结构、目标域检查、区间语义和情景输入来源。相关关系、条件情景值和训练集内表现，分别不能写成因果、保证或无条件预测。

## 6. 交接到正文前的检查

- [ ] 每个实质性小问都有直接答案和结果状态。
- [ ] 每个关键数字能回到结果登记、计算输出或明确来源。
- [ ] 每个图/表都写明一个主要主张、单位和不能支持的更强结论。
- [ ] 公式中的符号、量纲、数据定义和实现一致；不以方法名称跳过推导。
- [ ] 验证设计确实支持对应主张，失败、异质性和不确定性没有被总体指标掩盖。
- [ ] 结论没有越过因果、最优性、泛化或训练保证边界。
- [ ] 正文足以独立理解答案链；附录与支撑材料足以复算、审计和追溯。

通过故事板检查只表示写作前的**证据组织完整**；最终仍要执行 `paper-production.md`、结果对账、论文结构/数字/视觉审核以及当届规则、匿名和 AI 合规检查。
