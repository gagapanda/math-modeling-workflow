# 论文主张—图表—公式—结果—验证—边界与创新必要性卡

> 状态：第七轮隔离验证通过后纳入比赛写作路由。此卡不是图表数量、公式数量、页数或“创新点”数量配额；它要求每个核心主张都能被正确证据支撑，并明确不能推出的更强结论。

## 1. 什么时候使用

在以下任一情况使用本卡：

- 一张图/表要进入正文；
- 一个结果要写入摘要、结论或建议；
- 一个模型要被称为“更合适”“有必要”或“创新”；
- 论文存在“结果有了，但评委看不出它改变了什么判断”的风险。

它与 `paper-evidence-storyboard.md` 的关系是：故事板组织一问的完整答案链，本卡进一步把其中的核心主张拆成可审计的证据单元。

## 2. 核心主张卡（每条核心主张一张）

```text
claim_id：________________
question：Q__
claim_type：observation | association | prediction | scenario | causal | optimization
claim_text：________________________________________
decision_or_question_answered：____________________

source_data_and_version：__________________________
result_ids：_______________________________________
formula_or_model_ids：____________________________
primary_figure_or_table：__________________________
visual_or_tabular_encoding：_______________________
comparison_denominator_and_unit：__________________

visible_evidence：图/表中可直接观察到的事实是________________
interpretation：该事实支持的判断是________________________
validation_target：验证方法______对应主张________________
validation_result_or_failure_structure：_______________
claim_boundary：___________________________________
not_supported：该证据不能推出____________________________
body_appendix_split：正文保留______；附录/支撑材料保留______
result_status：draft | frozen | audited
```

### 2.1 主张类型边界

- `observation`：只陈述数据、轨迹、差值、分布或图中可见事实；不能自动升级为原因。
- `association`：陈述统计伴随关系；不得写成干预必然有效或统一方向。
- `prediction`：陈述给定模型、输入和目标域下的估计；必须交代验证对象、误差语义和外推风险。
- `scenario`：陈述把输入推进到指定参考线后模型给出的条件结果；不得写成已观测训练效果或承诺值。
- `causal`：只有设计、识别假设和验证真正支持时才可使用；小样本前后比较默认不能使用。
- `optimization`：必须交代候选集/搜索区间、约束、求解状态和比较口径；有限搜索只能称为条件最优或入选方案，不能称全局最优。

### 2.2 图表进入正文的最低条件

一张核心图/表必须同时回答：

1. 它支持哪一条具体主张，而不是“展示结果”；
2. 数据来源、版本、样本数、单位和比较分母是什么；
3. 读者在图/表中能直接看到的证据是什么；
4. 需要哪些正文解释才能从证据得到判断；
5. 它不能支持哪个更强结论；
6. 对应的结果 ID、公式/模型 ID 和验证记录在哪里。

图注应优先写成：

```text
图/表展示对象 + 数据口径/单位 + 编码含义 + 直接可见发现 + 支持的判断 + 不能推出的边界
```

不要求每张图都承载完整模型，但每个核心判断至少要有最合适的一张主图或表；重复图、装饰图和只增加页数的图应删除或移入附录。


### 2.2.1 图前—图注—图后的三段职责

核心图进入正文后，应让读者在局部范围内完成“为什么看图—图中看见什么—该事实如何用于后续判断”的闭环。三段是**功能分工**，不是强制要求三段都独立成段：

```text
图前：说明为什么需要这张图，以及表格、公式或单一数字不能回答什么
图注：说明展示对象、分面、编码、单位、样本/比较分母、直接可见事实与局部边界
图后：把可见事实解释为本问判断，并说明失败结构、验证、下游模型/决策或回退动作
```

执行规则：

- 图前只承担“为什么需要图”和“图与表/公式如何分工”，不要预先复述整张图的全部发现。
- 图注必须在脱离正文一小段时仍可解释展示对象。至少写出数据口径、单位、分母、颜色/线型/符号编码和直接可见事实；不能只写“结果见图”。
- 颜色不是唯一编码时，仍应说明线型、点形、参考线或分面；不得要求读者仅靠颜色猜测。
- 样本、有效配对或缺失导致分母变化时，必须在对应图注局部写出，不能只在数据章节统一交代。
- 图注只使用已冻结结果与登记过的舍入口径，不得借图注新增未经正文和结果登记建立的数字、显著性、成功率或因果解释。
- 图后不逐字重复图注，而要回答“这改变了什么判断、下一步怎样使用、失败时如何回退”；若图只承担描述功能，也应明确它不支持的更强结论。
- 关联图应阻断因果升级；条件预测或情景图应阻断训练效果与成绩保证；有限搜索图应阻断全局最优宣称。
- 情景图还必须解释横轴如何构造、参考线来自何种样本/规则、推荐节点是什么口径，以及安全或可实施性未被图中模型编码时由哪个下游判据审核。

版面服从功能闭环，不机械追求形式完整：

- 若分页会使图前句孤立在上一页，可把“为什么需要图”压入图注首句；这比保留一个与图分离的形式化图前段更可靠。
- 若图前、图注和图后能在同页或相邻可视区域完成职责，不要求为了凑三段而增加重复文字。
- 图和图注不得分离；核心图后的判断、验证或安全下游应尽量紧邻，不能跨页后只剩无法定位的“由图可知”。
- 不得通过缩小到不可读字号、压缩边距、删除单位/边界或牺牲图像清晰度来换取页数。

最小阻断条件：

- 图前、图注和图后全部塌缩为“结果见图”；
- 缺展示对象、单位、比较分母或关键编码；
- 把均值变化写成所有个体同向，把相关写成因果；
- 把情景曲线单调写成已观测训练效果，把推荐点写成全局最优；
- 情景图未解释横轴、参考来源或安全/可实施性下游；
- 图注或图后出现无法回到冻结结果登记的新数字；
- 最终 DOCX/PDF 中图、图注、图后解释发生分离、裁切、重叠或不可读。

比赛时间压缩时：

- **6 小时路径**：每张核心图至少保留“动机（可并入图注）+ 对象/单位/分母/编码 + 一条可见事实 + 一条局部边界 + 一句下游用途”。
- **12—18 小时路径**：在上述基础上补齐表图分工、异质性/失败结构、验证对应、回退动作、图表登记和最终逐页视觉检查。

### 2.2.2 表前—表题—表后的论证职责

核心结果表不能退化为“正文已经报完数字，表格再重复一次”。表前、表题、表体和表后应承担互补职责：

```text
表前：提出比较、对账或决策问题，或说明上游公式输出怎样进入本表
表题：局部声明对象、样本/有效分母、单位、验证协议和选择方向
表体：只承载已冻结、可复现、允许舍入后的精确值
表后：给出直接答案、同口径比较、失败/异质性、下游用途与不能推出的边界
```

执行规则：

- **表前不先写完答案。** 先交代“比较什么、为什么需要表、公式输出如何成为表中列或排序口径”；精确数字主要留给表体，避免表格成为重复报数。
- **表题与表头职责不同。** 表题声明整张表的对象、样本/分母、单位、协议和方向；表头只标识各列。不能因为表头写了 `MAE/m`，就省略“同一整对象留出协议、MAE越小越优”等全表口径。
- **表后必须把精确值转为判断。** 至少回答主要差异、失败或异质性、对本问答案/选模/决策的影响，并说明图、验证或下一步如何继续；不得只写“由表可知结果较好”。
- **公式后必须有输出桥接。** 说明公式输出进入哪张表、哪一列、按什么规则比较或选择。例如先按对象内汇总，再对对象等权平均，就必须明确表中排序的不是随机行级误差。
- **单位和分母必须局部可见。** 缺失导致有效分母变化时，表题、列名或表前/表后应就近说明；不同单位或无量纲指标不能按原始差值大小跨行直接排序“改善最大”。
- **统计量不能替代研究设计。** `p` 值不能替代效应大小、方向计数、有效分母、个体异质性和因果识别；非随机前后比较即使 `p` 值较小，也不能写成训练因果证明。
- **预测与情景表要冻结口径。** 选模表中的目标对象预测列不参与模型选择；条件情景表必须说明冻结映射、共同基准和输入节点，不得写成训练后实测成绩、成功率或统一精度保证。
- **表格和图应分工。** 表格负责精确值、单位、分母和舍入口径对账；图负责展示趋势、个体轨迹、异质性、失败结构或路径一致性。两者不能只是同一内容的重复装饰。
- **最终载体必须视觉闭合。** Markdown 中邻接不代表 DOCX/PDF 中邻接。表题必须与表头和至少首个数据行同页；短核心表原则上整表不跨页。表题孤立、表头与首行分离、短表被无必要拆页、裁切或列宽不可读，都应阻断交付。

若分页空间不足，优先采取：

1. 对表题设置 `keep with next`；
2. 对短核心表把表头和数据行作为一个不可拆散的局部块；
3. 压缩表题但不删除对象、单位、分母、协议或选择方向；
4. 把次要列、全量诊断或长文本移入附录；
5. 不通过缩小到不可读字号或删除边界换取同页。

比赛时间路径：

- **6 小时压缩路径**：每问至少审计一张核心表，使用一行速记：

  ```text
  表前问题/公式输出 | 表题口径 | 冻结值 | 表后答案 | 边界 | PDF同页检查
  ```

  优先保证单位、有效分母、协议、选择方向、直接答案和边界；非核心表可移入附录。
- **12—18 小时完整路径**：逐张核心表补齐来源/result ID、公式/模型 ID、有效分母、单位、舍入口径、验证协议、失败结构、表图分工、下游用途和 DOCX/PDF 页码；抽查表题—表体—表后是否形成局部闭环。

> 本节只规定表格如何进入论文论证，不证明表中数字、统计检验、模型或决策正确。表中数值仍必须来自冻结结果和可复现代码，并通过结果对账、验证与人工拍板。

## 2.3 摘要—正文—图表—结论跨位置一致性回放

同一核心主张出现在多个位置时，不能只做“全文出现过关键词”的全局检查；必须按位置检查其**数值口径、主张类型和边界**是否同时成立。

推荐采用以下分工：

```text
结果登记/正文结果表：冻结精确值、单位、结果 ID 和验证口径
摘要/结论：声明允许的可读舍入值，并保留主张边界
图注：声明图表口径、样本/比较分母、可见事实和不能推出的结论
```

最低检查项：

- 精确值只能来自冻结结果登记；可读值必须是预先声明的舍入表达，不能在摘要、正文、结论之间手工产生第三套数字。
- 同一主张在摘要、逐问正文、图注和结论中必须保持同一 `claim_type`；观察/关联、条件预测、情景规划不得在后文升级为因果、保证或无条件外推。
- **限制词不能挽救越界句干。** 在一句话的主谓宾层面先按 `claim_type` 写：情景应写“在给定输入推进规则下，模型给出……”，关联应写“在本样本中伴随……”，预测应写“在当前模型与目标域下估计……”。不能先写“训练会提高”“方案保证达到”“因素导致”，再在句尾补“仅供参考/不是保证”。
- 边界词要在**对应位置局部出现**，不能因为摘要写了限制，就默认结论或图注也安全；允许同义措辞，但必须预先登记。例如“不是已观测训练效果保证”和“不是已观测的训练效果保证”可视为同一边界族，但不能以空泛的“仅供参考”替代。
- 正文数字应能回到结果 ID、源文件和图/表；图表登记中的主张应能定位到实际图像和正文解释。
- 自动检查可以验证数值、ID、文件、位置和登记的边界字段；人工仍需判断语义是否真正成立、公式是否正确、图表是否有说服力，以及是否存在“加了限制词但整句仍过度承诺”的问题。

时间不足时，至少完成：

```text
每条摘要/结论主张
→ 一个冻结结果 ID
→ 一个正文/图表证据位置
→ 一个局部边界短语
→ 一个允许的可读精度
```
### 2.3.1 摘要与结论的高密度压缩

高密度不是把更多术语和数字塞进有限版面，而是让每个保留句子至少承担一个可审计功能。结果未冻结前不得做“终稿式”摘要和结论；冻结后按下列链条压缩。

摘要按小问优先组织为：

```text
任务/对象
→ 关键方法特征或数据结构
→ 直接回答题目的核心结果
→ 最关键的比较、误差或失败
→ 对应主张的局部边界
```

- “方法特征”写会改变结果解释的结构，如配对、分组留出、折内预处理、冻结模型、约束或情景规则；不要列完整算法目录。
- “核心结果”必须带必要的单位、样本/比较分母或基线。每问不要求数字越多越好，只保留直接回答题目和限制解读所必需的值。
- 误差、失败和边界应放在对应小问内，不能只在摘要末尾用一句“存在局限”统一兜底。
- 摘要可使用登记过的可读舍入值，但必须从冻结精确值机械得到；不得手工产生第三套数字。

结论优先组织为：

```text
冻结答案
→ 验证为何支持
→ 失败结构或误差异质性
→ 禁止升级的更强结论
→ 可复用结构、适用条件与新增数据需求
```

- 结论不是第二份摘要：可保留冻结精确值或统一精度值，并说明答案为何可信、哪里不稳定以及失效时如何回退。
- “优势”只能写已经实际执行、可以定位到正文或审计证据的设计特征，例如统一定义、配对结构、分组验证、冻结映射、约束检查和拒绝机制。
- “推广”必须写成条件句，说明需要新增的运动者、时段、外部样本、尺度标定、复测或独立验证；不得写无条件“可广泛推广”。
- 结论不得提出正文和冻结结果中没有建立的新发现，也不得把关联、预测、情景或有限搜索升级为因果、实测、保证或全局最优。

摘要—结论数字分工建议：

```text
冻结结果登记：唯一精确值及单位
摘要：声明允许的可读舍入值
结论：冻结精确值或与正文统一的报告精度
正文结果表/图注：精确值、比较口径、误差与结果 ID
```

同一主张只能有一个冻结来源和一组声明的显示精度。若摘要用舍入值、结论用精确值，必须自动或人工逐项核对二者同源；出现第三套数值、单位变化或主张类型变化时，停止润色并回到结果登记。

比赛时间路径：

- **6 小时压缩路径**：每问至少写出“方法特征 + 直接答案 + 局部边界”；整篇摘要再补一个最重要的验证或误差。结论至少写“冻结答案 + 不能推出什么”。如果篇幅不足，先删背景和算法清单，不能删主张边界。
- **12—18 小时完整路径**：每问补齐基线/分母、匹配验证、失败或异质性；结论增加验证为何支持、可复用结构、回退条件与新增数据需求，并执行摘要—正文—图注—结论跨位置回放。

应阻断的负例：

- 只有背景意义，没有逐问答案；
- 只有算法名称，没有核心数字；
- 只有结果数字，没有方法结构、验证或误差语义；
- 用随机行级交叉验证声称新个体外推；
- 把经验误差带称为严格置信区间；
- 把条件点预测称为实测成绩，把情景值称为训练保证或最优解；
- 摘要、正文和结论手工出现不一致数字；
- 用“效果理想、先进可靠、可广泛推广”等宣传词替代证据；
- 为了写满一页压缩掉单位、分母、失败或边界。

本组件通过只表示有限篇幅中的主张、数字和边界组织合理，不证明模型或结果本身正确；仍须绑定冻结结果、运行一致性检查并检查最终 PDF 首页和结论页。
## 2.4 核心公式—符号—现实解释—结果—验证闭合

关键公式不能作为孤立的数学装饰。对每个会改变数据定义、模型输入、预测值、优化决策或验证判断的公式，至少建立以下五段绑定：

```text
现实关系/约束
→ 公式
→ 符号、单位、取值域、索引与信息时点
→ 结果、决策或下一公式的用途
→ 验证口径、适用边界与不能推出的结论
```

最低要求：

- 公式前说明它把哪个现实对象、观测关系或约束转成数学量；不能只写“定义如下”。
- 公式后就近说明新符号、单位/量纲、取值域、索引含义和数据时点；跨段落寻找定义不视为稳定表达。
- 说明该公式的输出将用于哪一个结果表、图、预测、比较或决策；没有下游用途的公式应删除、移入附录或改成文字定义。
- 为公式绑定对应的验证记录：事件复核、量纲/范围检查、留出验证、敏感性、结果对账或人工视觉审查；并写明验证不能证明什么。
- 公式链中涉及重复测量、分组权重、训练/留出折、单位换算、预测与情景输入时，必须显式写出分母、权重、信息来源和变换顺序。
- 多于 3 个核心公式时，独立符号表为强制项；只有叙述性“符号说明”不算符号表。推荐字段：

```text
符号 | 含义 | 单位/域 | 首次出现/作用范围 | 结果或模型用途
```

每个核心公式可用下列登记卡验收：

```text
formula_id：
question：Q__
reality_relation：
equation：
symbols_units_domain：
next_result_or_decision：
result_ids：
figure_or_table_ids：
claim_ids：

```

### 材料性公式的局部验证见证

对会改变直接答案、模型选择、排序、阈值、可行性或情景动作的核心公式，在其进入结果桥前至少选择一个与数学类型匹配的验证见证，并就近登记：

```text
检查对象 → 期望关系 → 实际结果 → 允许范围/容差 → 失败后的拒绝、降级或重算动作
```

见证按题型选择，不强迫每条公式执行全部检查：单位/量纲，定义域、分母非零、概率范围或可行域，边界值或极限工况，解析恒等式，守恒量或单调性，代表性手算或回代，透明基线的方向/数量级，或真正独立的第二实现。

独立性分三级记录：

- **独立见证**：不同实现、解析解、人工手算、守恒关系或外部已核验工具，未复用同一错误路径；
- **半独立见证**：复用冻结输入，但以不同公式、不同聚合、边界值、数量级或原约束回代核对；
- **同路径自洽**：同一代码再次运行、同一公式反向回算或只检查求解器成功，只能发现部分传递错误，不能写成独立验证。

硬边界：同一代码成功运行不等于独立验证；单位一致不等于模型正确；一个代表性代入不等于全域证明；求解器成功不等于方程、边界、可行性或结果正确。见证失败时不得继续润色或冻结相应结果，必须按登记动作拒绝该结果、降级主张或返回定义/代码重算。

比赛时间压缩时，每问只保留 1—3 个真正支撑直接答案的核心公式，并为每个材料性公式给一个最小见证；可用一行短段，不强制新增章节或矩阵。时间不足时优先执行单位/定义域、代表性手算、边界值和原约束回代。

### 2.4.1 比赛版符号表与公式登记最小模板

此前论文中容易出现“有一段符号说明，但读者仍不知道符号、索引和结果如何对应”的问题。比赛版不要求把内部 ID 堆进正文，但要求每个小问至少有一个可独立理解的符号—公式单元。`不适用` 可以作为明确值填写，但不能留空。

**6 小时压缩版：每问一张最小卡。** 只登记真正支撑直接答案的 1—3 个核心公式，以及这些公式实际使用的符号；不要为未进入正文的中间量建立大而全的符号表。

```text
Q：Q__
直接答案：____________________________________________

符号表（核心公式出现的每个非显然符号各一行）
符号 | 含义 | 单位/域 | 索引/分组 | 信息时点 | 首次出现/作用范围 | 结果或模型用途
_____ | _____ | ______ | ________ | ________ | ______________ | ______________

公式登记
formula_id：________________
现实关系/约束：_______________________________________
公式：_______________________________________________
symbol_refs：_________________________________________
输出用途：____________________________________________
result_ids：____________  figure_or_table_ids：________
claim_id/type：_________  validation_ids：_____________
公式见证类型：__________（独立/半独立/同路径自洽）
期望关系：______________  实际结果/容差：______________
失败动作：拒绝结果 | 降级主张 | 返回定义/代码重算
不能推出：____________________________________________
status：draft | frozen | audited

一行绑定
Q | claim_id/type | formula_id | result_id/value/unit | figure_or_table_id | validation_id | 边界 | status
```

6 小时卡的验收条件：直接答案非空；每个核心公式都有现实解释、明确符号、下游结果和验证；每个符号都有单位/域、索引/分组和信息时点；结果至少 `frozen`，进入最终稿的图表和主张达到 `audited`。公式输出若没有下游结果或决策，应删除、改成文字定义或移入附录。

**12—18 小时完整版：在最小卡上扩展，而不是另起一套口径。** 增加以下字段：

```text
符号：来源/定义、首次出现位置、适用范围、变换前后单位、是否观测/估计/决策量
公式：关键推导步骤、假设/约束 ID、代码实现位置、替代定义或失败结构
结果：数据版本、程序版本/哈希、精确值、允许舍入、结果状态
图表/主张：正文位置、比较分母、主张类型、可见证据、边界、视觉审查记录
验证：验证对象、分组/时间切分、指标、结果、不能证明什么
```

完整版的正文组织建议固定为：

```text
本问直接回答
→ 变量与符号表
→ 现实关系和假设
→ 核心公式及关键推导
→ 参数/算法与实现口径
→ 结果表或主图
→ 验证与失败结构
→ 结果解释、边界和本问结论
```

符号表的作用是让读者能在不回查代码的情况下读懂公式；公式登记的作用是让队员能从论文主张回到结果、代码和验证。二者不能互相替代：只有符号表没有结果绑定，或只有公式 ID 没有可读符号定义，都不算闭合。
#### 符号表的正文布局与导出验收

全局符号表优先收录跨小问复用、会改变结果解释或容易产生口径歧义的符号；只在单个公式中出现的局部集合、排序下标和中间量仍应在公式附近定义。不要为了显得“完整”把所有代码变量复制到正文。紧凑版可以把“单位/域”和“首次出现/作用范围/信息时点”合并成一列，但单位、取值域、索引/分组和信息时点不得因此丢失。

版面与导出必须检查最终 DOCX/PDF，而不能只检查 Markdown：

- 全局符号表应尽量控制在一页；若一页无法清楚容纳，应按小问拆分，不得用不可读字号硬塞。
- 若符号表独立成页，下一主要章节应从下一页开始，避免数据审计、模型或结果段落孤立在符号表页尾。
- Markdown→Word/PDF 链若未处理表格单元格中的 LaTeX，出现原始 `$...$`、`\frac`、`\mathrm`、丢失上标/下标或符号错位时必须阻断交稿；应改用可读符号文本，或让表格单元格也经过原生公式注入。
- 视觉验收至少检查表头、符号、中文含义、单位/范围、分页和下一章节起始位置；“源码里写了公式”不等于交付 PDF 中公式可读。
- 符号表和公式渲染通过只证明表达链可读，不证明公式、模型或结果数学正确。

#### 符号说明—首次定义—选择性公式编号—正文引用一致性

符号表和公式编号的目标是降低评委定位成本并保持跨问追踪，不是制造数学复杂度。最终正文同时满足以下规则：

- 全局符号表只收跨段/跨问复用、会改变结果解释或容易产生歧义的符号；只在一个局部公式中出现的中间量在式前或式后就近定义。
- 每个高影响符号都要能定位含义、单位/域、索引/分组、信息时点和首次定义。版面紧张时允许把“单位/域”和“首次定义”合并为一列，但不能丢失其中任何信息。
- 在符号表前后统一声明索引作用域和字体身份，例如标量、向量、集合，以及个体、个体内试次、展开样本和特征索引。相同字母的标量、带下标集合和最终选定集合必须明确区分。
- 残差必须登记方向，例如“预测值减实际值”或“实际值减预测值”；后续经验区间、偏差符号和图表方向必须沿用同一口径。
- 只编号会被后文引用、用于验证、进入连续推导或被下游计算复用的核心公式。一次性局部定义不强制编号，禁止为了“公式丰富”给所有展示公式机械编号。
- 核心公式前写现实关系或约束，式后写输出是什么、进入哪张表/图/下一公式、采用何种比较或验证，以及不能推出什么更强结论。
- 正文引用的编号必须存在、唯一、连续，并与目标公式绑定；公式移动、删除或重排后，引用和下游结果定位必须一起重审。
- **源 Markdown 中存在 `\tag` 不等于最终 Word/PDF 显示编号。**必须分别检查源文件、DOCX 结构和最终 PDF 可见性，不能用源码检查替代交付物检查。
- 最终 DOCX/PDF 中，编号应与公式保持在同一逻辑段落或稳定容器内，不得重叠、裁切、漂移到下一行/页，或与错误公式绑定；发现任一问题即阻断交稿。
- 公式编号和符号表通过只表示表达接口可追踪，不证明公式推导、代码实现、模型选择或结果数值正确。

比赛时间路径：

- **6 小时压缩路径**：只编号每问 1—3 个真正支撑直接答案、跨段引用或跨问复用的核心公式；使用紧凑符号表，并人工抽查最终 PDF 中编号真实可见。
- **12—18 小时完整路径**：补做全部核心公式的首次定义、单位/域、索引/字体、残差方向、交叉引用、下游结果去向、DOCX 绑定和全 PDF 视觉审计。
**最小模板的阻断条件：**

- 任一公式使用了未登记符号，或符号缺单位/域、索引/分组、信息时点；
- 公式没有 `result_ids` 或 `validation_ids`，却进入核心答案；
- `audited` 公式/主张依赖 `draft` 结果，或结果尚未完成来源对账；
- 直接答案、结果、图表主张和边界无法通过 ID 在同一问内互相定位；
- 把符号表存在、公式结构完整或数字相同误写成数学正确性证明。
时间压缩时的保留规则：

- **6 小时压缩路径**：每问至少保留 1 个真正支撑直接答案的核心公式，并在公式邻近位置补齐现实关系、关键符号/单位、下一步用途和一个局部验证/边界；不追求展开全部推导。
- **12—18 小时完整路径**：补齐公式登记表、符号表、替代定义、推导关键步骤、量纲/范围检查、敏感性或失败诊断，并让公式 ID 与结果登记、图表主张互相可追溯。
- **时间不足时不得删除**：直接回答、核心公式、符号/单位、透明基线、验证、结果边界和结果冻结状态；优先删除新模型、非必要敏感性、装饰图、重复表和版式润色。

公式结构审计、人工数学审查、代码/结果对账和最终视觉检查是四个不同门：自动检查通过不代表数学正确，论文有符号表也不代表代码实现与公式一致。



### 2.4.2 两遍写作法：先闭环，后定向扩写

第十二轮以 2025 E 题 Q3 的同一份冻结结果做了 6 小时压缩版与 12—18 小时完整版对照。两版都保留了直接答案、独立符号表、核心公式、模型比较、图表主张、分组验证和适用边界；完整版增加的内容主要是数据层级、折内实现顺序、失败结构、目标域检查和经验误差语义。由此把“论文写得丰富”定义为**证据密度和解释闭环增加**，而不是公式、图表或字数增加。

**第一遍：最小证据闭环（所有核心小问强制完成）。**

```text
直接答案
→ 核心符号表
→ 现实关系/假设
→ 1—3 个真正支撑答案的核心公式
→ 结果表/主图
→ 与任务匹配的验证
→ 不能推出的边界
```

第一遍完成后，队员应能在不回查代码的情况下回答“算出了什么、怎么算、凭什么相信、不能说明什么”。任何核心数字在第一遍没有结果来源、单位、验证口径或边界时，不得进入摘要、结论或图注。时间不足时，保留第一遍，不用新模型、装饰图、重复表和教材式算法介绍换取表面丰富度。

**第二遍：只做有问题导向的定向扩写（有时间且与本问相关时完成）。** 每一段扩写至少回答一个评委可能追问的问题，并能绑定到公式/模型、结果、图表、验证或边界中的至少一项：

1. **数据层级和部署对象**：观测单位是什么，重复测量如何处理，预测/决策对象是谁，信息在何时可获得？
2. **关键推导或定义选择**：为什么这样归一化、建模或设约束；替代定义会产生什么变化？
3. **实现顺序与防泄漏**：填补、标准化、特征选择、训练和验证的先后如何保证口径不漂移？
4. **失败结构、异质性或敏感性**：哪些组误差较大、哪些参数/假设敏感，复杂模型带来了什么代价？
5. **不确定性、目标域和推广边界**：区间是什么语义，目标是否落在训练域，结论能推广到哪里、明确不能推广到哪里？

扩写准入条件：段落若不能改变读者对定义、证据、验证、失败或边界的理解，应删除或移入附录；不能用“显著”“有效”“创新”“稳健”等评价词代替同口径数字、图表或验证。模型选择仍须至少保留透明基线、比较指标和选择规则；相关性、条件预测、有限搜索和前后观察不得升级为因果、保证或无条件外推。

**比赛期间的版本选择：**

- 6 小时路径先完成第一遍，每问只维护一张最小卡；若还有余力，只补最能降低越界风险的一项扩写。
- 12—18 小时路径先完成所有小问第一遍，再按评委问题优先补五类扩写，优先补验证对象、失败结构和边界，而不是先做版式润色。
- 结果冻结后，扩写只能解释已冻结结果；若扩写引入新数字、新比较或新图表，必须回到结果登记、验证和主张审计，不能在正文中临时计算。

两遍写作法不是对最终页数的承诺，也不替代数学审查、代码/结果对账、视觉检查和规则合规审计。


### 2.4.3 结果段五步法：数字 → 比较 → 失败/异质性 → 现实解释 → 边界

结果段不得停留在“报一个最优数字，再说模型有效”。对每个核心小问，优先用以下五步形成可独立阅读的结果单元：

1. **数字与口径**：先写结果、单位、样本/分组/时间切分和指标；不要只写“效果很好”。
2. **同口径比较**：给出透明基线或预先声明候选，明确比较分母、绝对差异或相对差异，并说明选择规则。
3. **失败/异质性**：报告组间、时间段、情景或参数差异；若总体指标掩盖失败组，应把失败结构写入结果段。
4. **现实解释**：把观察到的关联、预测信息或优化结果连接回题目对象，但不把相关性改写成因果。
5. **边界**：明确验证证明了什么、没有证明什么；条件预测不写成实际结果，有限样本不写成统一保证，经验误差带不写成严格置信区间。

压缩版可以把五步压缩为一个段落或三句话，但不能删除“比较”和“边界”；完整版可拆成“结果与同口径比较—失败结构与现实解释—目标预测/不确定性与边界”三个小段，并附一张追溯卡。任何“更好/更稳/有效/准确/显著”的判断，都必须能回到同口径数字、主图/表和匹配验证。

结果段的最低验收字段：

```text
result_id/value/unit
→ comparison_baseline + comparison_rule
→ heterogeneity_or_failure
→ claim_type
→ validation_id
→ claim_boundary
```

结果段禁止：

- 只报告主模型、不报告基线或候选比较；
- 只给总体均值、不报告关键失败组或异质性；
- 用“姿态特征有效”“模型准确预测”“因素导致提高”等句式替代证据；
- 把模型比较观察、条件预测、情景结果或相关关系升级为因果、实际成绩、训练保证或无条件外推。


### 2.4.4 双层模型表达：结构图 + 公式链 + 结果图

第十四轮以 2023 A127、2023 C050、2023 E176 三篇代表性参考论文的文本—视觉联合复核为依据，确认复杂小问常同时需要两类表达：一类让评委快速看懂“步骤、对象和信息顺序”，另一类让评委核查“公式、比较和结果证据”。这不是增加图表配额，也不是把流程图当作证明。

**复杂小问的推荐编排：**

```text
直接回答
→ 符号与口径表
→ 结构图：数据对象/假设/信息时点/模型步骤
→ 公式链：现实关系 → 定义 → 目标/约束 → 求解量
→ 结果表或结果图：同口径比较与失败/异质性
→ 验证、解释与边界
```

三种载体的职责必须分开：

- **结构图负责“步骤如何发生”**：画出数据对象、决策对象、输入可用时点、预处理/训练/验证顺序和下游输出；不承担“模型更好”“预测可靠”或数学正确性的证明。
- **公式链负责“每一步怎么算”**：说明现实关系或约束、变量/单位/取值域、公式输出的下游用途，以及与公式匹配的验证记录；不能用结构图替代核心定义和目标函数。
- **结果图/表负责“凭什么选择”**：绑定冻结结果、比较分母、单位、样本/分组口径、失败结构和主张类型；不能用流程图替代基线、误差或方案比较。

**何时采用：**

- 6 小时路径：只有当一个小问同时包含多层数据变换、重复测量/分组、防泄漏或条件预测时，才采用紧凑结构图；优先保留公式、基线、验证和边界，结构图不得挤占结果证据。
- 12—18 小时路径：对复杂小问可采用“结构图 + 公式链 + 结果图/表”双层编排；先完成最小闭环，再补结构图和问题导向解释。
- 简单描述统计或单一公式小问：不强制制作结构图；若图不能减少评委理解成本，应删除或移入附录。

**最低登记接口：**

```text
route_figure_id
→ data_object / decision_object / information_order
→ formula_or_model_ids
→ result_ids / primary_figure_or_table
→ validation_ids
→ claim_boundary / not_supported
```


#### 全文总路线图：四问依赖与主张层级

全文总路线图不是目录的图形化版本，也不是每篇论文的强制项。只有当多个小问共享数据/定义、后问复用前问特征或模型，且各问主张类型容易混淆时，才考虑在问题分析之后、假设与符号说明之前增加一张总路线图。

总路线图至少应同时表达：

```text
共享数据与统一定义
→ 各问的数据/决策对象
→ 小问之间的真实信息依赖
→ 每问的主张类型（如 observation / association / prediction / scenario）
→ 不支持的因果、无条件外推或实际效果保证
```

准入与阻断规则：

- 箭头只能表示已在正文中存在的定义、特征、模型输入或结果依赖；若无证据支持，不得画成因果传递或效果机制。
- 总路线图负责“全文如何连起来”，局部路线图负责“某个复杂小问如何计算和验证”；若总图复制折内预处理、候选模型数字、误差区间或局部步骤，应删除重复内容。
- 总图优先不放结果数字，避免与摘要、结果表和局部路线图形成第三套数字；确需数字时仍必须绑定冻结结果和哈希。
- 只有四个平行框、没有共享口径和依赖关系的图不提供额外信息，应删除。
- 图前或图后必须说明职责，并明确各问公式、结果图表和匹配验证仍在对应章节独立给出；不得让总路线图替代技术证据。
- 必须在完整论文临时副本中连续检查前后至少 3—4 页。为把图提前一页而压缩问题重述/技术路线，可能使后续假设段或独立符号表产生新的半空页；应按连续页面的总收益判定，而不是只优化单页。
- 若总图增加一页但显著降低四问导航成本，且未破坏符号表、正文起始和原结果图，可接受；若比赛时间不足以完成最终 PDF 视觉验收，则不采用。

总路线图通过只证明全文导航、主张层级和版面闭合，不证明模型正确、因果成立、预测可外推或训练情景会实现。

#### 完整论文中的落位与分页验收

隔离样板通过后，结构图仍必须进入**完整论文临时副本**验证，不能只凭单图或单问样板判定可用：

- 结构图应出现在对应复杂小问的核心公式和结果比较之前，使阅读顺序保持“对象/步骤 → 计算定义 → 选择证据 → 边界”；不得把路线图放到结果之后作为装饰性总结。
- 图前正文必须说明它承担的数据对象、处理顺序和信息边界；图后正文必须明确它与后续公式、结果表/图和边界段的分工。只有图片、没有上下游文字绑定时不得进入正文。
- 图内数字只能来自冻结结果，并登记来源与哈希；若图中出现 MAE、预测值、区间或方案值，它们必须与结果登记和后续结果图/表一致，结构图不得私自计算第三套数字。
- 结构图应与结果图保留明显职责差异；若两图都只是重复同一数字或结论，应删除结构图或移入附录。
- 完整论文视觉验收应同时检查图前是否留下异常大空白、图注是否与图同页或紧邻、公式和表格是否被截断、原有结果图是否被挤散，以及正文页数增加是否与阅读收益相称。
- 不要为了让结构图独立成页而机械强制分页。若强制分页造成前页大面积空白，应优先保留自然分页、缩短图前文字或适度缩放图；只有自然分页导致标题孤立、图注跨页或图像裁切时才设置分页控制。
- 对复杂小问，新增一张高信息密度结构图可以占用额外正文空间，但必须通过全篇 PDF 逐页检查；“图已生成”或“Markdown 引用了图片”不等于最终 DOCX/PDF 已正确嵌入。

完整论文落位通过只证明结构、职责和版面闭合，不证明模型正确、验证充分或外部可推广。
**反例阻断：**

- 只有流程图就声称模型“最优、准确、适用于所有对象”；
- 只有公式和一个结果数字，却没有说明数据对象、信息时点、候选比较或验证对象；
- 为模仿优秀论文而固定每问图数、公式数或页数；
- 把参考论文的高密度版式直接吸收为方法结论，忽略其未复算、未验证或边界不足。

通过该双层表达检查，只证明论文把“步骤理解”和“证据核查”分配给了合适的载体；仍需完成公式/代码/结果对账、主张边界审计、最终视觉审查和合规检查。


### 2.4.5 模型建立段的连续推导链

复杂模型段不能停在“算法名称 + 最终公式 + 一个结果数字”，也不能为了显得充实而复制教材推导。第十八轮完整论文临时验证表明，只有当中间定义能连接现实任务、真实实现和下游结果时，扩写才有比赛价值。

**推荐链条：**

```text
现实任务/决策对象
→ 数据对象与信息时点
→ 当前状态、参考或输入向量
→ 中间量（差距、状态转移、目标、约束）
→ 模型路径/目标函数/预测映射
→ 实际求解或拟合口径
→ 冻结结果表/图
→ 验证、接受/拒绝或回退
→ 主张边界
```

每一步至少回答一个问题：

- **为什么需要它**：对应哪项现实关系、题目任务或约束；
- **怎么算**：变量、单位、域、数据来源和信息时点是什么；
- **代码实际怎么做**：是否重新拟合、重优化、填补、标准化、分组或使用目标标签；
- **下游用在哪里**：进入哪张结果表、图、验证或决策；
- **不能推出什么**：是否只是关联、条件预测、预设情景或局部优化。

**跨小问复用时的冻结表达：**

若后一问复用前一问模型，必须区分：

1. 复用相同模型定义、特征、训练数据和参数口径；
2. 直接载入同一序列化模型；
3. 按相同定义在同一冻结数据上重新拟合一次；
4. 对每个情景/方案重新拟合或重优化。

正文只能按真实代码选择相应措辞。不得把第 3 种写成“直接加载同一个模型文件”，也不得把第 4 种掩盖成“仅改变输入”。若不同方案不应重新拟合/重优化，必须把这一点写入公式链、实现说明和负例测试。

**情景模型的最低闭环：**

```text
current_state
→ reference_state（说明来源与为何选择）
→ gap_or_direction
→ scenario_parameter + declared_domain
→ scenario_state
→ frozen_prediction_or_objective_mapping
→ result_ids
→ acceptance/rejection rule
→ not_causal / not_optimum / not_guarantee
```

- 情景参数必须说明它是什么、又不是什么，例如不是训练时间、成功概率或优化变量；
- 参考分位数、行业值或目标线不得直接写成生理上限、最优值或必达标准；
- 预设离散节点不得包装成算法求得的最优解；
- 安全、可行或业务约束若只能人工审核，应明确写为操作性判据，不能伪装成数据拟合阈值；
- 必须给出失败后的拒绝、回退、重采集或重优化动作，只有“注意安全/符合实际”不算闭环。

**中间计算表的准入：**

只有当表能够把“输入 → 中间量 → 方案节点 → 下游结果”放在同一口径下，并显著降低复核成本时才进入正文。表内显示值若经过舍入，而程序使用未舍入值继续计算，必须注明显示值不参与再次运算；不能因读者用显示值复算出现末位差异而形成第二套口径。

**比赛时间路径：**

- 6 小时路径：至少保留“现实任务 → 核心定义/目标/约束 → 实际实现口径 → 结果 → 验证/边界”；中间量只保留直接进入结果或决策的部分。
- 12—18 小时路径：可增加向量化定义、紧凑计算表、接受/拒绝集合和失败回退，但必须先完成数字对账与最小闭环。
- 任何路径都不得用无下游用途的教材推导、固定公式数量或页面密度代替真实证据。

**负例阻断：**

- 只写“采用岭回归/遗传算法/灰色模型”，随后直接给结果；
- 公式中的中间量未定义、无单位、无数据来源或未在代码中实现；
- 把相关关系写成作用机制，把条件情景写成训练效果，把预设节点写成最优解；
- 声称“沿用上一问模型”，但代码实际重新选模、使用目标标签或对每个情景重新拟合；
- 增加完整算法教材推导，却没有任何冻结结果、验证或决策引用；
- 只写安全/可行口号，没有可验收的接受、拒绝和回退条件；
- 为增加内容密度导致结果图、结论或符号说明分页破坏，且未检查完整 PDF。

该链通过只证明模型段在“现实关系—计算定义—实现—结果—边界”之间形成可核查叙事，不证明模型本身正确、因果成立、方案安全或结果可外推。


#### 公式—冻结结果—表图—验证—结论的局部跨载体闭环

完整论文中的核心答案不应要求读者自行把分散载体拼接起来。每个关键小问至少应在结果段附近用一条局部闭环句明确：哪一个公式或定义生成什么量，哪张表冻结精确值，哪张图显示结构、顺序或异质性，哪项验证判断匹配程度，以及最终结论保留什么边界。

```text
核心定义/选择规则
→ 冻结结果或代表性数值代入
→ 主表精确对账
→ 主图检查结构/趋势/异质性
→ 匹配验证与失败结构
→ 直接答案 + 不可推出的更强结论
```

**只补决定结论所必需的中间桥：**

- 候选模型的入选必须写明同口径选择规则；相对改善百分比若进入摘要、结论或创新描述，应能由冻结表中的操作数直接复算。
- 条件情景、推荐节点或方案向量至少展示一个代表性数值代入，使读者能够确认公式、表格节点和结果数字属于同一口径；这不等于把每个节点全部手算展开。
- 表负责精确值和单位，图负责趋势、顺序、结构或异质性，公式负责定义与映射，验证负责判断证据是否匹配；任何一个载体都不得替代安全、可行、因果或外推边界。
- 多条证据链汇合时，应说明它们回答的对象层级和交集的含义；观察性配对变化与跨对象相关同时出现，只能提高筛选可信度，不能自动增强因果识别强度。
- 图像坐标、归一化量或代理特征若未标定，不得因公式—表—图一致就升级为真实米制位移、速度或机制参数。

**推导密度判定：**

- `过疏`：核心百分比、候选选择、推荐节点或情景提升只有结论，没有冻结操作数、代表性代入或结果表定位。
- `适中`：补入一至两个直接决定选择、结果或边界的中间式，并立即连接表、图、验证与结论。
- `过密`：展开无下游引用的教材算法、矩阵求解细节或全部样本计算，只增加篇幅，不改变选择、验证、解释或决策。

**最终制品与自动化验收：**

- Markdown 中出现公式或数字不等于 DOCX/PDF 中可见；新增推导必须检查公式未裁切、编号未漂移、表图未被挤散且没有原始 LaTeX。
- 核心编号只统计与公式绑定的可见标签；正文中的“式（7）”等合法交叉引用不能误判为重复编号。
- 保护核心表时，提取规则必须止于连续表格行；不得让跨段贪婪匹配把表后新增解释误判为表格被修改。
- 表题自动识别应要求“表号 + 空格/标题结构”，不能用 `startswith("表3")` 把“表3的选择规则……”误识别为表题。

**比赛时间路径：**

- 6 小时路径：每问至少保留“核心公式/定义 → 一个冻结结果或表 → 一张必要图或结构证据 → 一项匹配验证 → 一句边界”；只展开一个直接影响答案的代表性计算。
- 12—18 小时路径：补齐候选选择算式、代表性向量/方案代入、失败或异质性解释和跨载体局部闭环句，再做 DOCX/PDF 全篇视觉复核。

该闭环通过只证明不同表达载体在同一冻结口径下可追踪，不能证明模型数学正确、因果成立、方案安全或对新对象具有统一保证。

## 2.5 公式—结果—图表—主张统一接口与冻结顺序

公式、结果、图表和主张不能依靠“文件名看起来相关”或“数字碰巧一致”建立追溯。比赛期间应为每个核心答案保留稳定 ID，并让不同登记资产通过 ID 互相引用；但**不要把同一字段手工复制到四张表中**。每类事实只设一个权威所有者：

| 权威资产 | 最少持有字段 | 必须引用的下游/上游 ID |
|---|---|---|
| 公式/模型登记 | 定义、现实关系、符号/单位/域、实现位置、状态 | `result_ids`、`validation_ids`；必要时 `claim_ids`、`figure_or_table_ids` |
| 结果登记 | 精确值、单位、源文件/源字段、生成程序或版本、允许的论文舍入、状态 | `validation_ids`；由公式/模型、图表和主张反向引用 |
| 图表登记 | 图/表 ID、数据版本、生成脚本、单位/图例、正文位置、状态 | `claim_ids`、`result_ids`、`formula_or_model_ids`、`validation_ids` |
| 主张登记/故事板 | 主张类型与文本、直接答案、边界、正文位置、状态 | `result_ids`、`formula_or_model_ids`、`figure_or_table_ids`、`validation_ids` |

追溯 ID 主要服务于内部登记、故事板、结果对账和质量门，不要求把内部编号密集堆入最终论文正文。若当前案例的声明式质量门要求正文出现 `结果 ID`/`result_id` 标签，则按该门执行；否则正文保持自然表达，ID 放在写作源的登记块、注释或 QA 资产中。

### 2.5.1 状态语义与准入条件

统一只使用三个状态，不能把“文件存在”“脚本跑完”或“肉眼看过”直接写成 `audited`：

- `draft`：定义、数值、图表或措辞仍可能改变；不得进入正式论文的结论性数字和最终图表。
- `frozen`：该资产的权威内容和版本已经锁定，可供下游生成。公式/模型 `frozen` 表示定义、符号、实现映射和比较口径已锁定；结果 `frozen` 表示精确值、单位、源字段和允许舍入已完成对账。它们都不等于数学正确性证明。
- `audited`：在 `frozen` 基础上完成与本资产匹配的审查。图表需完成数据/脚本/结果对账和视觉复核；主张需完成类型、证据、验证、边界及跨位置一致性复核。自动审计通过仍不替代人工数学判断。

以下状态组合必须阻断交稿：

- 公式/模型没有 `result_ids` 或 `validation_ids`，却被写成已审计；
- 图表没有 `result_ids`、`formula_or_model_ids` 或 `claim_ids`，却进入正文；
- 图表或主张为 `audited`，但其依赖结果仍为 `draft`；
- 结果已经更新，论文、图注或结论仍保留旧值；
- 摘要、正文、图注和结论手工使用不同舍入口径，且结果登记没有预先声明；
- 只通过全文数字搜索确认“出现过”，却不能定位到正确小问、图表、主张和验证位置。

### 2.5.2 冻结与传播顺序

默认顺序是：

```text
数据版本/定义
→ 公式与模型口径冻结
→ 代码运行和结果对账
→ 结果登记冻结
→ 从冻结结果重生成图表/表格
→ 图表对账与视觉审查
→ 主张类型、验证和边界审计
→ 传播到摘要、正文、图注和结论
→ 最终结构、数字、视觉与合规审计
```

任何上游变更都要显式使受影响的下游状态失效：

- 公式、模型、数据版本或预处理改变：关联结果、图表、主张和论文位置回退为 `draft`；
- 结果精确值、单位或允许舍入改变：关联图表、表格、主张和全部论文位置标记为旧版本并重生成；
- 图表数据、脚本、编码或图注改变：重新做结果对账、图表主张审计和最终视觉检查；
- 主张类型或边界改变：重新检查摘要、逐问正文、图注和结论，不能只改一个位置。

不得通过手工改论文数字绕过结果登记，也不得在结果冻结后继续让图表脚本读取另一份临时数据。

### 2.5.3 比赛时间路径

- **6 小时压缩路径**：在既有结果登记之外，每问只维护一行紧凑绑定表：

  ```text
  Q | claim_id/type | formula_or_model_id | result_id/value/unit | figure_or_table_id | validation_id | boundary | status
  ```

  同一行完成定位，不另建四套重复台账；只有状态至少达到“结果 frozen、核心图表 audited、主张 audited”后，结论性内容才能进入正式稿。

- **12—18 小时完整路径**：公式/模型、结果、图表和主张可分表维护，并补充数据/代码版本、哈希或时间戳、允许舍入、正文位置、失败结构、视觉审查和变更传播记录。

- **10 秒定位目标**：随机抽取一条摘要或结论主张，应能在约 10 秒内由 `claim_id` 找到公式/模型、冻结结果、主图/表、匹配验证、边界和正文位置。该目标是比赛操作性验收，不是数学正确性证明；若无法定位，先补接口，不要继续润色。

### 2.6 跨题型正文密度与逐问段落配比

“内容丰富”不等于固定页数、公式数或图表数。逐问正文应按尚未闭合的证据缺口分配空间，而不是让每一问机械采用相同篇幅。跨机理/优化、几何/规划、数据/预测/优化和时序/监测题型复核后，可使用以下非固定顺序做局部诊断：

```text
对象、口径与假设
→ 模型/规则建立
→ 求解或实现口径
→ 结果与候选比较
→ 匹配检验、失败结构与敏感性
→ 直接答案、优缺点和不可外推边界
```

**按缺口补内容：**

- 定义和模型已经很密、检验很薄：优先补跨源一致性、缺失/边界敏感性、稳定输出对象、失败模式和禁止推出的结论，不再增加无下游用途的公式。
- 模型很长、结果很短：补冻结结果、候选对照、代表性数值代入和结果为何改变选择；不要用算法流程继续挤占结果解释。
- 图表很多、结论仍弱：给每张图表分配唯一主要职责，删除重复展示，并补“图中观察如何进入判断”和边界。
- 简单小问：允许短而紧凑；只要定义、结果、检验和边界闭合，不为追求篇幅扩写教材推导。
- 复杂小问：模型建立可以占主要篇幅，但其后必须出现可见的结果分析、同口径比较和匹配检验，不能仅由全文末尾一段泛化评价代替。

**检验段的最低四层：**

```text
跨载体/跨来源一致性
→ 已知缺失、阈值、窗口或边界对结果的影响
→ 当前可以稳定报告的对象
→ 当前数据禁止推出什么，以及尚需完成的验证
```

这里的“稳定”必须说明适用对象和数据范围，不得把“同一脚本在现有样本可复现”扩写成跨个体、跨时段或跨场景稳健。未完成的阈值、窗口、分组或跨试次敏感性检查必须写成待验证项，不能使用“已证明”“统一适用”等完成式措辞。

**优缺点必须绑定本题：**

- 优点至少指向一个已验证的结构、性能、解释或操作性增量；
- 缺点至少指向一个本题实际存在的数据、假设、验证、计算或外推失败；
- 改进必须与该失败一一对应，例如增加重复试次、改用分组/时间验证、补标定、扩大敏感性范围或建立拒绝与回退机制；
- “模型简单、精度高、适用范围广”等可替换到任意论文的套话不计入有效正文密度。

**版面与时间路径：**

- 6 小时路径：每问先保证“定义/模型—结果—一项匹配检验—边界”四段可定位；最薄处优先补验证和直接答案。
- 12—18 小时路径：在数字对账和最小闭环完成后，再补候选比较、失败结构、敏感性、代表性代入和本题化优缺点。
- 每次扩写后都要检查完整 DOCX/PDF。若新增文字导致标题孤行、图表断裂、大面积异常空白或正文/附录冲突，应先修复版面，不以页数增长作为通过依据。

**负例阻断：**

- 用固定“每问三公式两图一表”代替证据需求判断；
- 定义、算法或文献综述很长，却没有冻结结果、验证和直接答案；
- 只在全文末尾写一段“模型稳定、具有推广性”，各问没有匹配检验；
- 把中心估计、支持区间、拟合优度或随机行交叉验证包装成人工真值、统计置信、跨个体外推或因果证据；
- 把计划进行的敏感性检查写成已经完成；
- 为“丰富”重复相同图表、公式解释或结论。

通过本节只说明正文空间更贴合证据链，不证明方法正确或篇幅最优。最终仍以真实结果、验证、规则与全页视觉审计为准。
### 2.7 逐问直接答案—摘要—结论的压缩一致性

摘要不是正文的删词版，结论也不是摘要的数字堆叠。三者应形成同一证据主张在不同压缩率下的可追溯链：

```text
正文直接答案
→ 摘要压缩
→ 结论精确复述
```

每次压缩至少保留：

```text
回答对象
→ 核心数字与单位
→ 数据/验证层级
→ 主张类型
→ 最关键边界
```

**层级与证据强度不可压丢：**

- 配对层、行级、个体层、运动者层、时间层和场景层不得在摘要中合并成同一分析对象；若同一小问有两条统计链，必须分别说明各自用途。
- 摘要允许合理舍入，结论可给精确数字，但不得改变方向、分母、单位、样本口径、误差定义或结果意义。
- 正文中的观察性关联不得在摘要或结论中压成因果；条件情景值必须保留“条件、预设、非实测或非保证”边界。
- 随机行交叉验证不得压写成新个体、新运动者或未来时段外推能力；经验误差区间不得压写成总体置信保证。
- 点预测不能脱离区间、域外或适用域边界单独进入摘要；拒绝与回退条件若决定结果是否可用，也属于核心答案。

**逐问最小接口：**

每一问的摘要至少能回答：

```text
算了什么
→ 得到什么
→ 在哪个层级或结构上验证
→ 不能推出什么
```

结论应从冻结结果登记精确复述，不得手工重新计算或另换口径。正文、摘要、结论出现不同数字时，先停止润色并回到结果登记与口径核对。

**时间路径：**

- 6 小时路径：为每问建立一行 `对象 | 核心结果 | 验证层级 | 边界`，据此写摘要和结论；若一问存在两种统计对象，拆成两行或在同一单元明确分号分隔用途。
- 12—18 小时路径：建立逐问—摘要—结论矩阵，自动检查数字、单位、层级词、条件词和边界词，再人工复核压缩是否改变证据强度。

**负例阻断：**

- 把 13 个配对写成 13 名独立运动者；
- 把随机行交叉验证写成新个体泛化；
- 把观察性前后变化写成训练导致的因果效应；
- 把条件情景写成训练后已经实现的成绩；
- 删除经验误差区间、训练域外或拒绝边界，只保留点预测；
- 摘要和结论使用不同数字、分母、单位或舍入口径，却没有登记转换规则。

通过本节只说明三处表达没有改变同一证据主张，不证明原始模型、结果或验证本身正确。仍须以冻结结果、验证记录、论文对账和全页视觉审计为准。
### 2.8 假设—定义—适用边界的可追踪表达

假设章节不是通用免责段，也不应把单位、索引、缺失处理和现实机制混成一段。只登记会改变计算、验证或主张强度的材料性口径，并让每条都能定位到受影响小问及失效后的结论边界：

```text
类型
→ 采用口径
→ 影响范围
→ 核验方式
→ 失效边界
```

**先区分口径类型：**

- **现实机制假设**：对真实过程作出的简化，例如忽略某项机制或固定某个环境条件；若会改变模型结果，必须绑定敏感性、诊断或局限。
- **数据质量/观测假设**：关于测量、缺失、误差或样本代表性的判断；不得用“题目数据完全可靠”“观测误差可以忽略”代替数据体检。
- **计算约定**：坐标、单位、尺度、索引、编码和缺失值规则。它们决定实现口径，但通常不是现实假设。
- **操作性定义**：把现实事件或状态转换为可复现判据，例如事件帧、阈值、窗口或接受条件；必须说明判据变化时是否需要重算。
- **统计与验证层级**：独立样本、配对、重复测量、个体/运动者、时间或场景层级；验证方式必须与该结构一致。
- **目标对象与主张语义**：明确预测谁、优化什么，以及“相关”“预测”“规划值”等词允许表达的证据强度。

**最低可追踪要求：**

- 每条口径至少写明 `影响哪一问/哪一模型`，不能只写孤立编号或套话。
- 核验可以指向数据审计、阈值/窗口敏感性、分组或时间验证、单位检查、外部标定、人工复核、局限或拒绝/回退条件。
- 失效边界必须说明哪些更强结论不能推出；例如未标定像素不得推出真实位移或速度，随机行验证不得推出新个体外推，条件情景不得写成训练因果或成绩保证。
- 同一条口径若同时影响数据、公式和结论，应在相应章节保持同名或可交叉定位，不能在前置假设表中写一套、代码和正文另用一套。
- 假设表只保留材料性口径；纯实现细节放入数据血缘、代码说明或附录，避免前置章节变成操作手册。

**比赛时间路径：**

- **6 小时压缩路径**：每条一行维护 `类型 | 采用口径 | 影响小问 | 失效边界`；至少覆盖单位/尺度、缺失/索引、关键事件或阈值、重复测量/验证层级、目标对象和主张语义。
- **12—18 小时完整路径**：补充核验证据、敏感性或诊断位置，并与数据审计、模型定义、结果登记、局限和拒绝/回退机制交叉引用。
- 若假设或定义在结果冻结后发生变化，必须解除受影响结果的冻结状态，重跑相应计算与验证，再更新论文；不得只改文字。

**负例阻断：**

- “假设题目所给数据真实可靠”“误差可以忽略”，但没有数据审计、误差量级或敏感性依据；
- 把坐标、单位、缺失值和帧索引包装成现实机制假设；
- 写了阈值或事件定义，却不说明阈值变化、边界帧缺失或人工复核失败时怎么办；
- 把重复试次当独立样本，或用随机行交叉验证证明新运动者、未来时段或新场景外推；
- 目标对象在“单次试跳、长期平均、总体个体”之间漂移；
- 在假设表中提前宣称因果、无条件泛化、全局最优、实测成绩或成绩保证。

通过本节只表示前置口径可扫描、可追踪且能在失效时降级，不证明假设本身真实、模型正确或结果稳健。仍须由数据审计、匹配验证、敏感性、结果冻结和全页视觉审计共同验收。
### 2.9 标题层级、语言一致性与逐问导航

标题承担证据导航，不是装饰。评委只扫描标题列表时，应能恢复论文阶段、小问对象、模型或证据职责，以及正文、声明、参考文献和附录的边界。

**最低组织口径：**

```text
论文阶段标题
→ 题号 + 任务对象/直接答案类型
→ 定义、建模、求解、结果、验证或边界职责
→ 声明、参考文献与附录显式分界
```

执行规则：

- 同一篇中文论文的主要导航标题应使用同一主语言；程序文件名、变量、英文专名和 AI 等缩写可保留，不要求清除全部英文字符。
- 每问的上位标题至少包含题号和任务对象或证据职责。事件检测、配对关联、预测和条件情景不得都压成相同的“模型建立与求解”。
- 下级标题描述本节实际承担的任务，如定义、特征、候选比较、求解、误差、敏感性、局限、接受或回退；不能用标题代替正文证据。
- 标题层级必须稳定。`H1/H2/H3` 的升降只能反映真实结构变化，不能为调整字号或分页随意改变。
- 标题措辞不得升级证据强度：观察性关联不能命名为影响机制；条件预测不能命名为准确预测；有限候选或情景推演不能命名为全局最优、最优训练方案或成绩保证。
- 标题必须与正文、图表、题号和交叉引用相符。标题改变了任务类型、目标对象或主张语义时，应回到模型/结果登记核对，而不能只做语言润色。
- `AI 使用声明`、`参考文献`、`附录` 等边界应显式可见；不得通过降级标题、合并章节或移入附录来隐藏披露、引用或支撑材料边界。
- 标题改写属于表达优化时，应优先保持非标题正文、公式、数字、图表、代码和结果不变，并检查最终 DOCX/PDF 中标题不孤行、不裁切、不造成章节边界漂移。

**比赛时间路径：**

- **6 小时压缩路径**：导出或扫描 `H1/H2/H3` 列表，检查能否不看正文就恢复“前置口径 → 各小问 → 综合验证 → 结论 → 合规/参考/附录”的顺序；四问上位标题必须可区分。
- **12—18 小时完整路径**：逐项检查 `标题 ↔ 正文职责 ↔ 图表/公式 ↔ 题号 ↔ 交叉引用 ↔ 主张边界`，并在 DOCX/PDF 中复核分页、样式和章节分界。

**负例阻断：**

- 四个小问使用同一个泛化标题，评委必须阅读正文后才知道任务对象；
- 把预测写成“准确预测”，把条件情景写成“最优训练方案/成绩保证”，把关联写成“影响机制”；
- 为了字号或分页随意把二级标题改成三级标题；
- 标题写“模型验证”，正文却只有训练拟合或随机行交叉验证；
- 标题、图题、正文题号或附录索引互相错位；
- 隐藏或弱化 AI 使用声明，把参考文献并入附录，或让正文与源码附录边界不可见；
- 标题润色时同时手工修改结果数字、公式或结论，却没有解除冻结并重新验证。

通过本节只表示标题系统可扫描、语言和层级一致、且没有在标题中升级主张；不证明正文证据充分、模型正确或结果可靠。仍须绑定结果冻结、正文—图表对账、论文质量审计和最终 PDF 全页视觉检查。
### 2.10 贡献—验证—局限—推广的结论分区

结论区不仅要复述逐问答案，还要让评委快速区分“做成了什么、凭什么可信、哪里会失效、获得新证据后如何更新”。不要把答案、优点、局限和推广压成一个长段，也不要照搬优秀论文中缺少本题证据的宣传式评价。

**推荐分区：**

```text
四问冻结答案与直接回答
→ 方法贡献与验证依据
→ 局限与失效边界
→ 推广与更新条件
```

执行规则：

- **冻结答案**从结果登记复制，保留对象、数字、单位、样本或验证层级及关键边界；不得在结论中重新计算或换口径。
- **方法贡献**只能写本文实际执行且可定位的结构，例如统一定义、匹配单位、分组验证、冻结映射、拒绝与回退机制。算法名称或教科书性质本身不算本题贡献。
- 每项贡献至少绑定一项已执行的验证、结果或失败回退；没有性能收益时，应写成解释增量、可操作性增量或证据链整合，不能包装成算法创新。
- **局限**必须说明它限制哪一类结论：数据量限制精度、非随机设计限制因果、单次测量限制稳定性、域外对象限制外推、缺少真实尺度限制物理解释。只写“样本较少、模型有待改进”不合格。
- **失效边界**显式写出当前不能推出的更强结论，例如固定精度、训练因果、训练后必达、跨个体泛化或全局最优。
- **推广**写成新增数据或条件触发的更新动作：新增什么证据、重跑哪些步骤、重新验证什么、何时拒绝或回退；不得写成无条件适用于其他地区、人群、时段或场景。
- 结论分区属于表达重组时，优先保持结论区以外正文，以及既有数字、单位、图表、公式和主张强度不变；改写后必须检查 DOCX/PDF 中标题不孤行、章节边界不漂移。

**比赛时间路径：**

- **6 小时压缩路径**：为四个分区各写一个首句；至少交付“逐问冻结答案、最关键验证、最大限制、新数据后的第一更新动作”，不使用空泛优缺点。
- **12—18 小时完整路径**：建立 `贡献 | 对应证据/验证 | 失败或代价 | 限制的结论 | 新增数据后的动作` 矩阵，再压缩为结论正文；逐项核对摘要、正文直接答案、结果登记和图表口径。

**负例阻断：**

- 把岭回归、神经网络、遗传算法、分位数等通用方法名称直接写成“创新”；
- 使用“效果理想、精确度高、可靠性强、准确预测”，却没有同口径结果和验证；
- 在没有证明时写“全局最优”，或把有限候选比较写成最优方案；
- 把观察性变化写成训练因果，把条件情景写成训练保证或实测成绩；
- 只列“样本少、时间紧”，不说明哪些结论因此失效；
- 把推广写成“可广泛应用”，却不写新增数据、重跑步骤、验证和回退条件；
- 为改善结论观感而手工修改冻结数字、增加无来源公式、图表或更强结论。

通过本节只表示结论中的答案、贡献、验证、局限和推广条件可扫描且证据边界清楚，不证明模型正确、贡献新颖、预测准确或可以外推。仍须绑定结果冻结、逐问验证、正文—图表对账、规则合规和最终 PDF 全页视觉审计。
### 2.11 正文引用—参考文献—方法依据可追溯性

参考文献的作用不是增加数量或装饰“学术感”，而是让外部来源在正文中有真实、唯一、可复核的用途。建议按下列链条检查：

```text
外部事实 / 题目数据 / 软件文档 / 方法来源
→ 正文首次实质使用位置
→ 唯一编号引用
→ 文后完整条目
→ 本文实际用途
→ 本题自己的选择理由、实现与验证
```

执行规则：

- **首次实质使用处建立接口**：题目附件在数据审计或首次整体使用处引用一次；软件组件在第一次承担读取、变换或求解职责时引用；后续重复使用不机械堆引。
- **文献数量不是质量指标**：正文没有实际用途、无法核验或与代码实现不一致的条目不应保留。少而真实、用途清楚、编号闭合优于多而失配。
- **软件文档只支撑实现语义**：文档可以说明接口、组件、参数或读取规则，不能证明模型适合本题、结果正确或验证充分。
- **方法文献不能代替本题证据**：历史来源和一般性质不能替代透明基线、同口径候选比较、数据结构判断、敏感性或验证结果。
- **自定义实现保持正确归属**：项目自行编写的秩、检验、交叉验证、搜索或后处理流程，应按实际代码说明；不得为了增加权威感而归因给未导入或未调用的第三方库。
- **编号必须双向闭合**：每个正文编号都应有唯一文后条目，每个文后条目都应有明确正文用途；删除、交换或新增条目后必须重新检查编号顺序和正文定位。
- **引用不越过冻结门**：补引和参考文献纠错不得顺带改动冻结数字、公式、图表、模型、结论强度或 AI 使用声明；需要改变事实时先解除冻结并重新验证。
- **资料来源不等于结果来源**：课程、优秀论文或软件文档可用于发现方法和解释定义，但当前论文中的数据、数字、图表和结论仍须来自本题代码、结果登记和验证证据。
- **完整条目必须能够唯一识别并复核定位**：题目资料至少写明竞赛、年份、题号与题名；期刊论文至少保留作者、题名、期刊、年份、卷期与页码等已核验字段；在线软件文档至少保留机构、页面题名、产品/版本、真实访问日期与可访问定位地址。`用于……`只能补充本文用途，不能替代著录元数据；不得凭记忆补造 DOI、网址、期号、页码或访问日期，也不得在未核验标准全文时宣称完全符合某一著录规范。

**比赛时间路径：**

- **6 小时压缩路径**：只为真正进入正文的题目数据、关键外部事实、核心软件接口和非通识方法建立首次使用引用；交稿前完成一次“正文编号集合 = 文后条目集合”检查，并删除没有用途的条目。
- **12—18 小时完整路径**：建立 `来源 | 首次使用位置 | 支撑命题 | 实际代码/数据用途 | 本题选择证据 | 禁止推出` 对照表；逐项核对源码导入、调用、参数和自定义流程，再检查 DOCX/PDF 中编号、条目和分页可见性。

**负例阻断：**

- 文后列出大量来源，但正文没有编号接口；
- 在每次出现同一软件名时重复引用，遮蔽论证主线；
- 用“文献表明该方法先进”代替本题基线比较和验证；
- 把自行实现的检验、分组验证或搜索流程写成第三方库功能；
- 保留未实际使用的软件包或方法条目，或补造正文句子为条目寻找用途；
- 引用不存在的编号、保留未被引用条目、交换条目后不更新正文；
- 用参考文献支撑未经运行的性能、显著性、因果性、全局最优或外推结论；
- 为改善引用观感而修改冻结结果、增加无来源数字、公式或图表。

通过本节只表示外部来源、正文用途、文后条目和实际实现之间可追溯，不证明文献本身正确、模型选择合理、代码无误或结果可外推。仍须绑定来源核验、代码—结果对账、结果冻结、论文质量审计和最终 PDF 全页视觉检查。
### 2.12 模型输出—现实解释—决策含义的局部闭环

论文表达的最小可复核单元不是“公式 + 由此可知”，而是：

```text
模型输出
→ 现实对象/统计语义
→ 本问判断
→ 下游选模、反馈、接受或回退动作
→ 适用边界
```

**执行规则：**

- 每个核心公式、核心模型或核心图表后，明确写出模型实际输出的对象、单位/域和统计语义；不要让读者自行猜测“这个数代表什么”。
- 紧接着说明输出对应的现实对象或观察关系，例如事件中心帧、运动者层均值、分组预测误差、条件情景值；区分观测量、估计量、预测量和决策量。
- 每个输出至少连接一个本问判断或下游动作：筛选候选因素、选择主模型、接受/拒绝情景、触发复测、回退基线或限制结论。没有下游用途的公式应删除、改为文字定义或移入附录。
- 公式中的变量必须与全局符号表、公式附近定义和代码语义一致；发现下标、帧/时间索引、平滑前后变量或残差方向漂移时，先修正作用域，再进行论文润色。
- 结果段采用“数字/结构 → 比较或证据 → 现实解释 → 决策含义 → 边界”顺序。不能只写“结果表明”“由此可知”而不说明证据如何改变行动。
- 现实解释不得升级证据强度：相关性不得写成因果性，条件情景不得写成训练后保证，随机行级验证不得写成新个体或新运动者外推能力。
- 解释和决策含义必须保留对象、信息时点、验证层级和样本边界；“当前数据支持采用”不等于“现实中必然有效”。
- 输出—解释—决策闭环通过只表示表达链完整，不证明模型正确、结果稳健或决策在现实中有效；仍须绑定数据审计、结果登记、验证、冻结、图表对账和人工拍板。

**比赛时间路径：**

- **6 小时压缩路径**：每问至少写清四句：`输出是什么`、`现实上代表什么`、`改变哪个判断/动作`、`不能推出什么`。每个核心公式只保留真正服务于直接答案的公式，并在邻近位置给出关键符号和单位。
- **12—18 小时完整路径**：补齐 `formula/model ID | output type | result ID | figure/table ID | validation ID | decision/action | boundary` 对照；对失败结构、替代模型和回退条件做局部说明，并在最终 DOCX/PDF 中检查公式、定义、图表和段落没有被分页拆散。

**负例阻断：**

- 公式后只写“由此可知”，没有输出语义或下游用途；
- 用一个预测值直接写成训练效果、成绩保证或无条件外推；
- 把“与成绩相关”改写为“导致成绩提高”；
- 只报告平均误差，不说明分组方式、对象层级和对实际判断的影响；
- 公式使用了未定义符号，或把帧索引、时间索引、平滑变量混用；
- 为增加论文“丰富度”堆砌没有结果、验证或决策去向的公式、图表和背景；
- 结果已冻结后，为改善表达顺手改动数字、模型、图表或结论强度而未重新审计。

**最小记录模板：**

```text
Q：Q__
formula/model_id：____________
output：模型直接产生什么量？单位/域/统计语义是什么？
reality：它对应题目中的哪个现实对象或观察关系？
claim：本问据此作出什么有限判断？
decision/action：它改变哪个选模、反馈、接受、拒绝或回退动作？
validation_id：____________
result_id / figure_or_table_id：____________
boundary：不能推出什么？失效时如何降级？
status：draft | frozen | audited
```

## 3. 创新必要性卡

不要从方法名倒推创新。按下列顺序写：

```text
现实缺口：题目中的对象/决策为什么不能只用现成的透明基线回答？
→ 基线不足：基线在本数据和本任务上漏掉了什么？
→ 增加的结构：主模型只增加了哪一项可解释结构？
→ 作用机制：该结构如何连接数据、公式和决策？
→ 预先声明的比较：用什么同口径指标与基线/候选比较？
→ 验证收益或解释增量：误差、可行性、稳定性或决策解释增加了什么？
→ 代价与失败：复杂度、样本需求、异质性、外推或不稳定性是什么？
→ 边界结论：可以称为哪一种“改进/整合”，不能称为什么？
→ 最终决策：因此在什么条件下采用，何时回退基线？
```

建议在正文中区分：

- **算法创新**：提出或改造了算法本身，并有对照证据；
- **结构建模创新**：把题目特有机制、约束或层级结构显式写入模型，并显示收益；
- **证据链/应用整合**：把事件、比较、预测、情景反馈串成可复核闭环。它可以是论文贡献，但不能包装成新算法。

至少报告一项收益和一项代价。若没有可核验的性能收益，应改写为“解释增量”“可操作性增量”或“候选方案”，而不是“创新模型显著优于基线”。

## 4. 比赛期间的快速用法

- **6 小时压缩路径**：每个核心小问只填 `claim_text`、`result_ids`、`primary_figure_or_table`、`validation_target`、`claim_boundary` 五项，先保证主张不越界。
- **12—18 小时完整路径**：补齐全部字段，并完成创新必要性卡；主模型进入正文前必须有基线对照和失败/代价记录。
- **结果冻结后**：把 `result_status` 改为 `frozen`，再复制到摘要、正文结论和图注；冻结后不得手工改数字。

## 5. 交稿前抽查

- [ ] 每条摘要/结论主张能定位到一张主图/表或明确结果登记。
- [ ] 每张正文核心图/表只有一个主要主张，且图注含口径、单位和边界。
- [ ] 每个“更好/更优/更稳/更创新”都有同口径基线或候选对照。
- [ ] 相关性、条件预测、有限搜索和前后观察没有被写成因果、保证或全局最优。
- [ ] 创新描述同时写出新增结构、可核验收益、代价和适用边界。
- [ ] 符号表、公式/模型 ID、结果 ID、验证记录和正文位置互相可追溯。
- [ ] 正文保留独立理解所需证据链，附录保留全量诊断、代码和审计证据。

> 通过本卡只表示主张与证据的组织契约完整，不证明模型、数值或图表本身正确；仍需运行结果对账、纸面质量门、视觉审查和规则/匿名/AI 合规审计。
















## 6. 逐问直接收口与主模型入选说明

### 6.1 逐问直接收口

核心图表之后，应先用一句可独立阅读的直接回答完成本问局部收口，再补验证、限制和下游用途。推荐顺序为：

```text
直接答案（对象 + 冻结数值/方向 + 单位）
→ 图表各自承担的证据职责
→ 验证结论与不确定性
→ 不能推出的更强结论
→ 该结果是否进入下一问
```

直接答案不得只写“见图/见表”，也不得把中心估计、支持区间、误差区间或条件情景混成同一种结果。若本问没有可靠数值答案，应明确写“未复现/证据不足”，并登记来源、差异和禁止推出的结论。

### 6.2 主模型入选说明

主模型入选必须同时写清：

```text
同口径比较协议
+ 可核验的选择收益
+ 保留的透明性或现实可解释性
+ 适用边界与失败代价
```

不得让读者误以为“特征更多、算法更复杂或名称更新”本身就是入选理由。若主模型仅在当前候选集、当前样本或当前验证协议下更好，应把这个条件直接写入正文；若没有稳定收益，则回退透明基线，或把复杂方法降为补充分析。

### 6.3 快速抽查

- [ ] 每个核心小问在主图/表后有一句直接回答，而不是只做过程复述。
- [ ] 直接回答中的数字、单位和对象与冻结结果完全一致。
- [ ] 图、表、公式和文字分别承担明确职责，没有重复堆砌。
- [ ] 主模型入选句同时包含比较协议、收益和透明性说明。
- [ ] “更多特征/更复杂方法”没有被当作性能或创新证据。
- [ ] 直接回答后仍保留验证边界，不把相关、条件预测或有限搜索升级为因果、保证或全局最优。

> 本节只规定表达与证据组织方式；它不能替代模型验证、数值对账、视觉检查或规则合规审计。
## 7. 正文语体分层与工程事实降噪

### 7.1 正文优先服务题目判断

正文应优先写现实对象、模型关系、结果数值、验证和边界；结果文件名、哈希、流水线状态、内部检查动作和全量证据清单放在附录或支撑材料。推荐分工为：

```text
正文：题目对象 → 计算关系 → 直接结果 → 验证 → 限制/决策
附录：文件路径 → 结果 ID/哈希 → 全量诊断 → 源码与复现顺序
```

可追溯性不能依赖正文反复列出 `results/...` 路径。正文可写“完整结果见附录A的支撑文件清单”，附录再保留精确文件名和版本绑定；若缺少附录或支撑材料，则不得仅为语言自然而删除必要定位信息。

### 7.2 必要工程事实只正式定义一次

当“固定模型、固定参数、折内预处理、结果冻结”是防止信息泄漏或保证复现所必需的事实时，应在首次出现处完整定义，例如：

```text
情景计算沿用问题3已经选定并拟合的模型；不同情景不重新选模、不重新拟合，只改变输入特征。
```

后文使用“固定模型”“同一参数”或“当前结果”等自然简称，不在每段重复“冻结、对账、登记、审计、闭环”。只有词语承载新的技术区别时才再次使用，不能机械删除科学上必要的状态说明。

### 7.3 语体优化的验收边界

语体改写只改变表达层，不得改变：

- 数字、单位、样本分母和舍入口径；
- 模型定义、候选比较协议和验证对象；
- 公式、图表证据职责和结果状态；
- 相关、预测、情景、因果与优化主张的边界；
- 失败条件、回退动作和未复现结论。

### 7.4 快速抽查

- [ ] 技术正文没有无必要的内部路径、哈希或流水线状态。
- [ ] 表前和图后先说明题目对象与判断，而不是先写“对账/登记/审计”。
- [ ] 固定模型或结果冻结只在首次定义处完整说明，后文自然简称仍保持防泄漏事实。
- [ ] 结论先回答各问，再说明方法贡献和适用边界。
- [ ] 附录仍保留精确文件、结果登记、源码和复现顺序，正文降噪没有破坏可追溯性。
- [ ] 改写前后所有数字、公式数量、图表数量、验证协议和禁止推出的强结论一致。

> 本节优化的是评阅阅读流，不降低证据标准，也不把“语言更像竞赛论文”当作模型正确或获奖的证明。


## 8. 摘要—正文—结论的信息层级与记忆焦点

### 8.1 三个位置承担不同压缩率

同一主张在三个位置必须保持对象、方向、单位、样本分母、验证对象和边界一致，但不要求重复同样多的数字：

```text
摘要：任务对象 + 一个关键方法/结构 + 1—2 个代表性结果 + 最重要边界
逐问正文：完整定义 + 中间节点/候选比较 + 图表证据 + 验证与失败结构
结论：冻结精确答案 + 可信依据 + 局限/回退条件
```

摘要可使用由冻结精确值机械舍入得到的可记忆精度；正文和结论保留结果登记中的精确值。舍入不能改变方向、排序、阈值判断、区间语义或是否达标。

### 8.2 代表性数字优先于中间节点堆叠

当一个小问同时产生多个过程节点、候选值或敏感性结果时，摘要只保留评委回答题目所需的记忆锚点。例如条件规划可优先保留：

```text
可执行规划值
+ 关键参考线/上界情景
+ 接受、拒绝或回退条件
```

中间推进节点、全量候选预测和精确小数留在正文、结果表或结论精确层。只有中间节点本身是题目直接要求、用于证明非单调/失效结构，或会改变最终决策时，才进入摘要。

### 8.3 压缩不能靠删除限制换取

摘要缩短或聚焦后仍必须局部保留决定主张强度的事实：

- 配对、重复测量或分组层级；
- 验证对象和误差语义；
- 外推、域外或小样本风险；
- 观察性关联的非因果边界；
- 条件情景的非实测、非保证含义；
- 结果是否需要安全复测、拒绝或回退。

如果压缩后使相关看起来像因果、点预测脱离误差与域外风险、情景值像训练承诺，必须回退旧版本。

### 8.4 结构化比较闸门

重大摘要改写不以“更短”或“更像优秀论文”为通过标准。至少检查：

1. 摘要每问能否快速定位；
2. 摘要—逐问直接答案—结论的数字、单位、对象和边界是否一致；
3. 代表性结果是否比中间过程更醒目；
4. 是否保留验证、失败和不可推出的强结论；
5. 结论精确层是否被摘要改写意外污染；
6. 主要符号说明、公式、图表和附录证据是否仍完整。

可使用去版本标识、固定顺序随机种子和预先冻结量表的内部 A/B 比较，但必须明确它不是独立评委盲评。新版本只有在一致性门全部通过且固定量表不低于旧版本时才保留。

### 8.5 快速抽查

- [ ] 摘要每问只保留任务、关键结构、代表性结果和最重要边界。
- [ ] 摘要使用可记忆精度，正文/结论精确值可由同一冻结来源追溯。
- [ ] 多节点结果在摘要中突出决策锚点，而不是罗列全部近似值。
- [ ] 验证对象、样本层级、域外、非因果、非实测和回退条件没有被删弱。
- [ ] 结论先给冻结精确答案，再说明可信依据和局限，不成为第二份过程摘要。
- [ ] 改写后的 DOCX/PDF 已重建并逐页检查，符号说明仍存在。

> 信息密度的目标是提高单位阅读时间内的正确理解，不是提高术语、方法名或数字数量。优秀论文只能提供表达参照，不能替代本题的结果登记、验证和边界。

## 9. 核心公式的局部叙事闭合

### 9.1 公式不是孤立展品

核心公式应在局部范围内形成可阅读、可计算、可核验的闭合链：

```text
现实对象
→ 符号与输入
→ 公式/定义
→ 各项如何计算或承担什么职责
→ 输出单位与进入哪张表、图或直接答案
→ 验证对象与不能推出的更强结论
```

不要求每个公式都写成六段。定义、推导、换算和目标函数承担的职责不同，但读者不能只看到一个通用公式而不知道它为何属于本题、如何得到结果或结果回答了什么。

### 9.2 公式前后的最低职责

公式前至少交代：

- 现实对象和计算目的；
- 本式首次出现的关键符号、数据来源、样本层级和必要单位；
- 若来自上一式，说明输入如何传递，而不是让读者自行猜测。

公式后按需要交代：

- 定义式的正负号、方向、集合成员或阈值语义；
- 目标函数各项、权重、惩罚项、截距和固定超参数的职责；
- 单位换算与量纲是否闭合；
- 公式输出进入哪张表、图、候选比较、验证指标或逐问答案；
- 该式只支持定义、描述、预测、情景还是优化，不能推出什么因果、外推、最优或保证结论。

公式后不得留下“计算。”“求解如下。”等无主语残句，也不得仅写“代入得结果见表”而省略关键口径。

### 9.3 区分定义、恒等换算、模型假设和推导

- **定义式**：说明符号如何构造以及正负、方向或集合含义，不包装成理论推导。
- **恒等换算**：说明单位和尺度恢复，例如厘米除以100换成米；不得借换算解释变量的因果作用。
- **模型假设/目标函数**：说明每一项为什么进入计算、固定参数如何确定以及候选定义边界；固定参数不等于已证明最优。
- **真正推导**：只有当前一关系在明确条件下推出后一关系时才称推导，并写出所用条件。代数展开、套用通用公式或重复抄写教材定义不算创新。

### 9.4 控制公式丰富度

公式数量不是论文充实度指标。一个公式只有在至少改变以下一项时才值得进入正文：

- 计算关系或模型定义；
- 约束、候选集或验证口径；
- 单位、尺度或样本层级；
- 结果解释、失败条件或决策。

若公式只提供通用背景、与本题结果无连接，或正文已有更清楚的文字/表格，应删除或移入附录。不得为了模仿优秀论文而堆叠偏度、峰度、相关系数等教材公式，也不得用长推导伪装创新。

### 9.5 修改与验证闸门

公式叙事改写默认只改变公式前后的说明，不改变公式本体。完成后至少检查：

- [ ] 公式块、编号和公式文本与冻结版本一致；
- [ ] 数字、单位、样本分母、模型定义和验证对象未变化；
- [ ] 摘要、结论精确层和主要符号说明未被意外改写或删除；
- [ ] 公式后的解释没有新增因果、全局最优、外推保证或性能保证；
- [ ] DOCX 中原生公式与编号仍完整，PDF 无原始 LaTeX、裁切、错位或跨页断裂；
- [ ] 若少量必要解释导致分页变化，已逐页检查并确认只是合法内容顺延；
- [ ] 正式案例、数据、代码、结果和图表资产哈希保持不变。

> 局部叙事闭合的目标，是让评委在公式附近回答“这是什么、怎么算、算出什么、为何可信、不能说明什么”，而不是让版面看起来公式更多。

## 10. 核心结果表的局部叙事闭合

### 10.1 表格承担比较与决策职责

核心结果表应在局部范围内形成可追溯的阅读链：

```text
为何需要比较
→ 比较对象、分母、单位与验证口径
→ 表内冻结数值
→ 表后第一句指出最重要的行列、方向与直接决策
→ 公式、图或后续步骤继续解释
→ 不能推出的因果、外推、最优或保证结论
```

表格不是数字仓库。评委读完表格后，不应还要跨过一张图、一个公式或数段文字才能知道哪一行最重要、当前选择是什么以及这一选择受什么边界约束。

### 10.2 表前、表题与表后第一句的最低职责

表前至少说明：

- 为什么需要该表，比较用于回答哪一问或支持哪项决策；
- 比较对象、样本层级、有效分母、单位和验证协议；
- 若某一列不参与选模、检验或排序，应在表前或表后就近声明。

表题应尽量包含对象、单位和关键比较口径，使表格脱离正文一小段距离后仍能被正确阅读。

表后第一句优先给出：

- 最重要的行、列或节点；
- 差异方向与必要的代表性精确值；
- 当前协议下的直接判断、入选、拒绝、执行顺序或回退条件。

公式和图可以继续解释降幅、异质性、趋势或证据结构，但不应把最基本的直接判断推迟到它们之后。已有直接答案若位置过晚，优先移动而不是复制。

### 10.3 分母、统计量和情景表的边界

- 配对表应明确有效配对数和差值方向；分母变化必须在局部写出，不能让读者从空白单元格推断。
- `p` 值、相关系数或均值差只支持其统计口径，不自动升级为因果效应。
- 误差表只排序当前候选集与当前验证协议；随机行级交叉验证不能证明新个体外推，目标对象预测列不得反向参与选模。
- 优化、搜索或参数表只有在约束和搜索范围已声明时才能支持相应求解结论；有限候选中的最低误差不等于全局最优。
- 情景表必须区分当前值、条件预测、实测结果和训练保证；最高节点不能自动成为推荐节点，安全或可接受判据仍具有否决权。

### 10.4 控制表格丰富度

表格只有在能够提高以下至少一项时才值得保留：

- 多对象、多指标或多情景的可比较性；
- 样本分母、单位、误差和不确定性的透明度；
- 模型选择、执行顺序、接受/拒绝或回退决策；
- 正文与结果文件之间的对账效率。

不要把正文逐句拆成表格，也不要在表后逐行复述全部单元格。表内保留冻结证据，表后只提炼最重要判断和失败边界；次要明细可以进入附录或结果登记。

### 10.5 修改与验证闸门

结果表叙事改写默认只调整表前后文字和阅读顺序，不改变表格单元格。完成后至少检查：

- [ ] Markdown 与 DOCX 的表格数量、行列和全部单元格文本与冻结版本一致；
- [ ] 数字、单位、有效分母、模型候选、验证协议和决策规则未改变；
- [ ] 直接答案只出现一次，并位于表后、图或进一步公式之前；
- [ ] 摘要、结论精确层、公式、图和主要符号说明未被意外改写；
- [ ] 表后没有新增因果、普遍优越、新个体外推、全局最优或训练保证；
- [ ] DOCX/PDF 已重建，表题与表格未分离，表格未异常跨页，表后第一判断与下一节没有形成孤行或不自然分页；
- [ ] 正式案例、数据、代码、结果和图表资产哈希保持不变。

> 局部叙事闭合的目标，是让评委在表格附近立即回答“为什么比、按什么口径比、哪一项最重要、据此做什么、不能说明什么”，而不是让表格看起来数字更多。

## 11. 相邻证据载体的职责分离

### 11.1 先分配职责，再决定写多少

相邻的表、公式、图和正文不应连续承担同一项复述任务。默认职责为：

```text
表 = 精确比较、单位、分母、候选与决策
公式 = 定义计算关系、约束、换算与生成机制
图 = 趋势、异质性、轨迹、异常、结构与失败形态
正文 = 直接回答、证据综合、现实含义与结论边界
```

这只是默认分工，不是机械格式。若题目需要图中读取精确拐点、公式本身就是最终答案，或表格用于展示失败结构，可以调整职责，但必须说明为何该载体不可被更简单的表达替代。

### 11.2 图后正文优先写“只有图能显示什么”

图后第一段优先回答：

- 汇总均值是否掩盖个体轨迹或分组差异；
- 总体误差是否掩盖留出对象之间的异质性；
- 是否存在非单调、离群、缺失、边界、饱和或失效区域；
- 情景路径是否内部一致，以及图中缺少哪些安全、可执行或因果信息；
- 这些结构如何改变结论强度、选模、接受、拒绝或回退动作。

若精确数值已经由紧邻结果表承担，图后不再逐项重复全部均值、候选误差或情景节点。必要时只保留解释图形结构不可缺少的代表性范围、分母、阈值或异常点。

### 11.3 自解释图注与图后论证不是一回事

图注应使图脱离正文一小段距离后仍可正确阅读，通常包含对象、面板、单位、样本层级、线型或颜色含义。图后正文则负责把图形证据纳入论证：它说明该结构支持什么判断、改变什么决策以及不能推出什么更强结论。

因此：

- 图注可以说明“左图比较候选误差，右图显示留出对象误差”；
- 图后正文应说明“总体排序是否掩盖个体差异，以及这如何限制外推主张”；
- 不要因为图注已经自解释，就完全省略图后判断；
- 也不要把图注改写一遍作为图后正文。

### 11.4 删除的是重复表达，不是关键证据

职责分离不等于盲目删数字。以下信息即使相邻载体已有部分呈现，也不能因“避免重复”而删除：

- 题目的直接答案和当前决策；
- 会改变解释的单位、有效分母、验证对象或缺失结构；
- 选择、接受、拒绝、回退所依赖的阈值或判据；
- 相关而非因果、条件情景而非训练保证、当前候选最低而非全局最优等边界；
- 图中无法编码但对落地安全、域外风险或结果状态至关重要的信息。

删除重复数字后，评委仍应能沿局部阅读路径回答：表给出什么精确证据，公式定义什么规则，图揭示什么结构，正文据此作出什么判断。

### 11.5 修改与验证闸门

相邻证据载体的职责调整默认只改载体前后的解释段，不改冻结证据。完成后至少检查：

- [ ] 图文件、图题/图注和图的 Markdown 引用与基线一致；
- [ ] 表格数量、行列、全部单元格、单位和分母与基线一致；
- [ ] 公式块、编号和公式文本与基线一致；
- [ ] 摘要、结论精确层和主要符号说明未被意外改写；
- [ ] 删除的数字仅为已在相邻载体中完整承担的重复项，没有删除直接答案、关键范围、阈值、异常或边界；
- [ ] 图后段确实增加趋势、异质性、轨迹、异常、结构或失败形态的信息，而不是换一种措辞复述表格；
- [ ] 没有新增因果、普遍优越、新对象外推、全局最优或训练保证；
- [ ] DOCX/PDF 已重建并逐页检查，图、图注、图后段和下一节之间无裁切、孤行或异常分页；
- [ ] 正式案例、数据、代码、结果和图表资产哈希保持不变。

> 职责分离的目标，是让每个载体贡献新的、不可替代的证据功能，提高内容充实度与阅读效率，而不是把论文压缩得更短或把数字机械去重。

## 12. 逐问段落的句间逻辑层级

### 12.1 先识别句子角色，再检查相邻关系

逐问段落中的句子通常承担以下角色：

```text
M = 方法、定义或计算口径
R = 结果、观察或直接答案
V = 比较、复核或验证证据
B = 证据边界、不能推出的结论
A = 采用、拒绝、回退或下游动作
```

角色用于审计，不是固定句式。无需让每一段机械具备 M—R—V—B—A，但相邻句之间必须有可说明的关系：方法产生什么输出，结果由什么证据支持，验证支持到什么强度，边界如何改变结论或动作。

### 12.2 不同证据必须说明是并列、互补还是层层推出

同一段中出现多类证据时，应写清它们各自回答的问题。例如：

- 候选模型预测集中，只检查当前候选集内部的敏感性；
- 整对象留出误差，回答当前验证协议下的预测误差；
- 目标对象是否处于训练域内，限制结果对该对象的适用性；
- 观察性配对变化与跨个体相关可以互补筛选因素，但二者的交集不升级为因果识别；
- 情景曲线单调可以检查固定模型下的路径一致性，但不构成训练后的外部效果验证。

不要把不同层级的证据压在一个“说明”或“因此”之后，使读者误以为它们互相证明。

### 12.3 连接词必须服从证据强度

`因此`只能引出前文实际支持的判断。若前文只有相关、内部一致性、候选集稳定性或小样本分组验证，后文不能升级为因果、外部泛化、统一精度或训练保证。

`但`、`然而`和`另一方面`应引入真正改变结论强度的反证、风险或适用条件，而不是添加与决策无关的免责声明。引入边界后，后文必须相应降低主张强度、扩大不确定性、改变交付形式，或触发拒绝、回退和补采数据。

`可见`、`说明`和`证明`不是证据本身。使用时必须能指向具体结果表、公式、图形结构、验证协议或复核记录，并且动词强度不能超过这些载体实际支持的结论。

### 12.4 验证句与边界句应共同决定交付形式

高质量段落不是先给强结论，再在末尾堆限制。应让验证和边界共同形成最终答案。例如：

```text
候选内部集中
+ 整对象留出误差
+ 目标对象域外风险
→ 点预测 + 宽误差带 + 域外声明
```

```text
坐标检测与可见姿态阶段相容
+ 缺失帧对事件边界的影响
+ 未完成跨试次敏感性检查
→ 可复现的操作性事件结果，而非人工真值或可推广阈值
```

边界句只有在改变主张、精度、采用方式或后续动作时才有信息增量；若删去边界后结论完全不变，说明它可能只是装饰性免责声明。

### 12.5 避免机械化分层

逻辑清楚不等于每段都写“第一、第二、第三”。只有证据种类确实不同且容易混淆时，才显式分层。对于已经闭合的短段，保留自然叙事；不要为了满足检查表而增加空洞连接词、重复结果或形式化编号。

比赛期间优先做高影响最小修正：先审计直接答案、模型选择、验证、外推和决策段，只改逻辑关系不清或可能导致强主张误读的位置。已能清楚完成证据合成的段落应保留。

### 12.6 修改与验证闸门

句间逻辑调整默认只改解释段的组织、连接和限定语，不改变冻结证据。完成后至少检查：

- [ ] 每个改动句能标明其主要角色，且相邻关系可解释；
- [ ] `因此`没有把相关升级为因果、把内部一致性升级为外部验证、把候选预测集中升级为新对象精度证明；
- [ ] 不同证据的并列、互补或推出关系已经写清；
- [ ] 边界句改变了主张强度、交付形式、接受/拒绝/回退或补采动作，而不是只作结尾免责声明；
- [ ] 没有机械要求每段都出现全部 M—R—V—B—A 角色；
- [ ] 摘要、结论精确层、主要符号说明、数字、单位、分母、公式、表格、图和直接答案未被意外改写；
- [ ] DOCX/PDF 已重建并逐页检查，分层后的段落没有造成孤行、异常分页、裁切或与下一节失去联系；
- [ ] 正式案例、数据、代码、结果和图表资产哈希保持不变。

> 句间逻辑层级的目标，是让读者知道每一项证据究竟支持什么、不能支持什么，以及这些边界如何改变最终答案，而不是让段落拥有更多连接词。

## 13. 正文—附录职责与复现入口

### 13.1 先以当届官方规则确定源码和附录位置

正文、附录和支撑材料的分工不能仅凭课程模板或往届习惯决定，必须先核对当届官方规则。以已核验的 2026 年全国大学生数学建模竞赛规则为例：正文不超过 30 页，附录页数不限；完整可运行的源程序既要收入论文附录，也要收入支撑材料压缩包。因此，不能为了减少总页数而删除源码附录，也不能把这一要求未经核验地推广为所有竞赛的通用规则。

正文应独立完成评委首读所需的闭环：

```text
直接回答 + 核心定义或推导 + 关键结果 + 验证 + 证据边界
```

附录负责提供复核入口、完整源码和必要的明细证据，而不是替正文补上缺失的直接答案、关键模型、核心结果或有效性说明。

### 13.2 附录入口优先使用可检索的证据导航

不要用一个长段落堆叠文件名。若支撑材料包含多个层级，可在附录入口使用如下表格：

```text
证据类别 | 路径或入口 | 支撑范围 | 复核用途
```

至少使评委能快速找到：运行入口或 `workflow.json`、处理后数据、逐问结构化结果、结果登记表、源程序目录、AI 工具使用详情和最终归档清单。随后给出一条短复核路径，例如：

```text
运行入口
→ 结构化结果或结果登记
→ 正文数字与图表
→ 论文附录源码及支撑包同名源码
```

导航项必须与最终提交包的真实内容一致：不得列入只存在于内部审计目录、临时副本或未提交工作区的路径；论文与支撑包分开提交时，也不得错误声称论文文件位于支撑材料压缩包中。

### 13.3 “完整源码”要求依赖闭包，而不只是顶层脚本

列出若干主脚本不等于提供完整可运行源码。冻结前应沿本地依赖检查：

- 主入口与逐问脚本；
- 本地导入的共享模块和包初始化文件；
- 配置、模板、参数或资源文件；
- 构建论文、生成图表或形成最终结果所必需的辅助脚本；
- 规则要求同时出现于论文附录和支撑包中的其他运行文件。

只要顶层脚本依赖未收入的本地模块，“完整源码”主张就不成立。依赖检查应以实际导入、调用和运行入口为证据，不能只看文件名或目录层级。

### 13.4 附录源码必须与最终正式源码和支撑包同步

论文附录中的代码块不能停留在较早版本。最终冻结前，应使用内容哈希或规范化文本比较，逐文件核对：

```text
论文附录源码
= 最终正式源码
= 最终支撑材料压缩包中的同名源码
```

发现差异时：

- 空白、换行或尾部空行差异也应在冻结前统一，避免出现多个不可判定版本；
- 任意实质差异，即使只遗漏一个字段、一条返回项或一个依赖文件，也会阻断“完整源码”结论；
- 当旧附录与最终正式源码冲突时，应同步附录，而不是为了保留旧版排版而维持过期代码；
- 同步后重新构建 DOCX/PDF，并再次检查标题连续性、代码尾部、分页和最终归档内容。

### 13.5 修改与验证闸门

正文—附录职责调整完成后至少检查：

- [ ] 当届官方规则已经核验，正文页数、附录范围、源码位置和支撑材料要求没有凭经验推断；
- [ ] 若改动仅限附录，正文在附录前的内容和冻结证据保持不变；
- [ ] 正文能够独立给出直接答案、核心定义或推导、结果、验证和边界；
- [ ] 附录入口采用可检索的证据导航，所有列出的路径都存在于最终提交物；
- [ ] 运行入口、结果登记、AI 工具使用详情和最终归档清单可被快速找到；
- [ ] 所有本地依赖已经闭包，顶层脚本、共享模块、配置或必要资源没有遗漏；
- [ ] 论文附录源码、最终正式源码和支撑包同名源码逐文件一致；
- [ ] 附录标题与源码编号连续，最后一个源文件的末尾完整可见；
- [ ] DOCX/PDF 已重建并逐页视觉检查，新增表格和长源码没有裁切、重叠、异常空白页或断尾；
- [ ] 正式案例、数据、结果、图表和其他冻结资产哈希保持不变。

> 正文—附录分工的目标，是让评委先在正文获得完整论证，再用附录和支撑材料高效复核；它不是把关键推理藏入附录，也不是为缩短总页数牺牲当届规则要求的完整源码。


## 14. 贡献主张的全文落位与证据分工

贡献不是只在摘要或结论中出现的评价词。准备把某个结构称为“贡献”“改进”或“创新”前，先建立一条可回放的全文链：

```text
技术路线预告
→ 正文首次证明位置
→ 对应图/表/公式/比较或失败证据
→ 验证强度、代价与边界
→ 结论回收
```

每项候选贡献至少登记：

```text
contribution_id：____________________________
contribution_type：定义 / 数据组织 / 模型 / 验证 / 决策结构 / 证据链整合 / 其他
real_gap：本题原有现实或证据缺口________________
added_structure：本文实际增加了什么结构__________
route_preview：技术路线中的预告位置______________
first_proof_location：正文首次证明位置____________
evidence_carriers：公式 / 表 / 图 / 比较 / 失败 / 复测 / 约束 / 其他
baseline_or_ablation_status：同口径基线、消融或无此证据
verified_gain：已验证的性能、解释、组织、验证或决策增量
cost_or_failure：代价、失败组、异常、额外假设或重算成本
claim_boundary：适用对象、分母、时间窗、目标域和不能推出什么
conclusion_recovery：结论回收位置________________
allowed_label：允许称谓__________________________
forbidden_stronger_label：禁止升级为______________
```

### 14.1 全文各位置的职责

- **技术路线只预告**：说明本文将解决哪些缺口、增加哪些结构，以及各自在哪一问建立；不能用路线图或一段“创新点”替代正文证明。
- **正文首次证明位置负责定义和证据**：第一次出现贡献时，应同时交代现实缺口、增加结构、关键数据/公式/图表以及该位置能支持的判断。优先把这句话放在原有模型、结果或验证段旁，不为宣传新增孤立标题。
- **验证节负责证据强度和失败**：说明基线或消融口径、总体收益、分组失败、敏感性、计算或数据代价，以及证据尚不能推出什么。
- **结论只回收**：按正文首次证明位置回收已成立的贡献，并与逐问答案、局限和更新动作分开；结论不得首次提出贡献、增加新比较或抬高主张强度。
- **摘要只保留最重要的一项或少数结构特征**：摘要中的贡献短语必须能回指正文首次证明位置和冻结证据，不能反复复制结论中的宣传句。

### 14.2 贡献类型与证据类型必须匹配

- **定义/测量贡献**可证明口径可复现、边界可审计；不能自动声称检测精度提升、人工真值或新算法。
- **数据组织贡献**可证明分母、匹配单位或层级与数据结构一致；不能自动声称因果识别、样本扩充或跨个体外推。
- **模型贡献**只有在同数据、同切分、同指标、同预处理和同搜索预算下存在基线比较时，才能写性能改善；没有比较时只能写结构或解释增量。
- **验证设计贡献**可证明验证对象更接近部署对象或更少泄漏；内部重采样不能包装成外部验证或固定泛化保证。
- **决策结构贡献**可证明约束、情景、拒绝、复测、停止或回退动作更可执行；不能把条件预测写成实测效果、训练保证或全局最优方案。
- **证据链整合贡献**可证明输入、输出、依赖、失效和重算可追溯；不能包装成算法创新。

### 14.3 性能归因与消融闸门

同口径整体模型优于基线，只能支持“这套候选结构在当前协议下改善了指标”。若没有逐组件消融、受控替换或其他可识别证据：

- 不得把整体收益归因于单一特征、单个预处理步骤、某个权重、参数优化或组合模块；
- 不得因方法名称包含“改进型、融合、自适应、优化”就声称创新；
- 可以如实写“当前证据不能分离各组件贡献”，并把进一步消融列为更新动作；
- 若贡献仅提供解释、组织、验证匹配或决策可执行性，应使用对应称谓，不强制制造性能提升。

### 14.4 普通实现不自动构成贡献

以下内容本身不能进入贡献清单：使用多种软件、增加图表数量、复现教材方法、一般参数调节、把两个模型串联、换一个优化器名称、使用 AI 辅助、代码可以运行。只有它们解决了明确缺口，并有匹配证据、失败和边界时，才可作为更大贡献链的一部分。

没有材料性贡献时，可以只写“本文采用透明、可复现的标准方法完成任务”，不得为满足模板而虚构创新点。

### 14.5 比赛时间路径

- **6 小时压缩路径**：对每项准备写入摘要或结论的贡献，只填 `类型 + 首次证明位置 + 一项证据 + 一项边界`；找不到首次证明位置时删除该贡献主张。
- **12—18 小时完整路径**：完成贡献登记，逐项回放技术路线、正文、验证和结论；只有存在同口径基线或消融的项目才能绑定性能收益，并在最终 PDF 中检查贡献句是否与证据邻接、是否造成孤立标题或页数膨胀。

### 14.6 修改与验证闸门

贡献落位属于表达重组时，默认不改数据、公式、表格、图文件和冻结结果。完成后至少检查：

- [ ] 每项贡献有唯一 `contribution_id` 和正文首次证明位置；
- [ ] 技术路线只预告，结论只回收，贡献没有在结论中突然出现；
- [ ] 贡献类型与证据类型匹配，仅有同口径比较或消融时才写性能改善或组件归因；
- [ ] 定义、数据组织、验证、决策和证据链增量没有包装成算法创新；
- [ ] 教材方法、软件数量、图表数量、模型组合和普通调参没有被当作自动创新；
- [ ] 公式、图、表、多重集和冻结数字与改写前一致，标题层级没有无意义膨胀；
- [ ] 摘要、正文、验证和结论的对象、方向、单位、分母、验证对象和边界一致；
- [ ] DOCX/PDF 已重建并逐页检查，无孤立贡献标题、裁切、重叠、乱码或末页异常膨胀。

本节通过只表示贡献表达的落位、证据绑定和主张边界更清楚；它不证明贡献具有学术新颖性，也不证明模型、结果或验证本身正确。

## 15. 分析集形成、样本流与有效分母

### 15.1 先区分数据载体、分析单位与验证单位

当数据经历筛选、匹配、分组、重复测量、插补或训练/验证划分时，先建立：

```text
原始候选范围
→ 筛选、匹配或分组规则
→ 实际分析单位
→ 每项核心主张的有效分母
→ 未进入、插补或分母缩小原因
→ 验证单位
→ 能支持与不能支持的结论
```

不得混用文件数、记录行数、试次数、独立对象数、配对数、群组数和验证组数。公式或结果表中的 $n$ 必须说明是哪一种单位；同一对象的重复记录不能因为占多行就被写成多个独立对象。

### 15.2 每项主张绑定自己的有效分母

- 配对差值使用可追溯配对数，并同时说明这些配对覆盖多少独立对象；
- 重复测量、混合效应、分组验证或整对象留出，同时报告记录行数、独立对象/群组数和验证组数；
- 某一特征局部缺失时，只缩小受影响指标的分母，除非整条分析单位确实不可用；不得让成绩、角度、相关、预测和情景沿用一个虚假的统一分母；
- 插补后的可计算分母与原始观测分母承担不同信息状态，必要时分别报告；
- 参考总体、训练总体、验证总体和目标对象职责不同，不能相加制造更大的“总样本量”；
- 跨问题复用同一批数据不增加独立信息量，不能把各问的 $n$ 相加。

样本流清楚只证明分母和主张可追溯，不证明样本规模充分、缺失机制可忽略、模型正确或具有外部泛化能力。

### 15.3 正文何时使用分析集表

只有出现至少三个材料性流转节点或多种分母职责时，才在数据审计段使用一张紧凑表：

```text
分析用途 | 候选范围 | 实际分析单位与有效分母 | 未进入或缩小原因 | 可支持的主张
```

表后仍应在各问首次使用处报告局部分母。若只有一次简单筛选，在对应小问用一句“原始 $N_0$→按规则排除 $r$→最终 $N$”通常更快。机理、几何或确定性优化题若没有材料性的筛选、重复测量、分组或验证单位变化，不强制制造样本流表。

### 15.4 比赛期间的最小登记

对每个会改变核心主张分母的分析，至少记录：

```text
question_or_analysis
source_scope
candidate_unit / candidate_count
analysis_unit / effective_count
independent_group_count
pairing_or_grouping_rule
missing_or_excluded_reason
imputation_status
validation_unit
claim_supported / not_supported
source_evidence
```

登记可以放在数据审计日志或结构化结果中，不要求再造一套重型 Schema。正文只抽取影响判断的行；完整明细留在结果或支撑材料中。

### 15.5 修改与验证闸门

- [ ] 文件数、行数、试次数、对象数、配对数、群组数和验证组数没有互换；
- [ ] 每个核心结果、公式和图表能回指自己的有效分母与分析单位；
- [ ] 局部缺失没有被误写成删除整个试次，插补值没有被伪装成原始观测；
- [ ] 同一原始数据没有跨问相加制造“大样本”；
- [ ] 随机行级验证没有被写成新个体、新设备或新站点外推证明；
- [ ] 分母变化能回指来源、筛选/配对规则和未进入原因；
- [ ] 样本流表只在材料性变化足够多时进入正文，且 PDF 中完整、可读、不跨页断裂；
- [ ] 无材料性样本流变化的机理/优化题没有被强制套表；
- [ ] 新增表达没有改变冻结数字、公式、图表、模型、结果或主张强度；
- [ ] DOCX/PDF 已重建并逐页视觉检查，正式案例和其他冻结资产哈希保持不变。

> 分析集表达的目标不是把数据写得更多，而是让每个数字的独立信息量、有效分母和证据边界一眼可见。



## 16. 算法可执行叙事、求解状态与代码映射

### 16.1 公式链与算法链分工不同

公式链说明现实关系如何被定义、推导和计算；算法链说明程序如何把真实输入转化为输出。模型已有充分公式时，不要用重复推导制造篇幅，应补足执行顺序、状态、分支/循环、停止或选择条件和输出资产。

```text
输入与数据状态
→ 初始化或参数装载
→ 材料性循环/分支/折分
→ 停止、筛选或选择条件
→ 输出结果与验证资产
→ 求解状态、可复现入口与结论边界
```

### 16.2 只描述真实执行的步骤

- 每个会影响结果解释的步骤，至少绑定一个真实源码函数、模块、求解器状态或结果文件；函数名只承担追溯职责，不能替代数学和业务解释；
- 明确输入行数、对象/组数、候选集合、初始化状态、折分单位、预处理位置、输出文件和检查点；重复测量不得在算法叙事中被偷换成独立样本；
- 有限候选或有限折的确定性枚举，须写“全部预声明候选/折已评估”及实际选择规则，不写“算法收敛”“全局最优”或外部验证通过；
- 随机算法才要求登记随机种子、重复运行和稳定性/误差证据；优化求解器应记录 `success/status/message`、约束可行性和最优性边界；没有这些证据时，不得补写伪造的迭代状态；
- 流程图只在存在材料性循环、分支、多阶段搜索或状态转移时使用；简单闭式计算用一句执行说明即可，避免图文重复。

### 16.3 结果段的最小执行表

当算法步骤包含至少两个材料性循环/分支，或读者无法从邻近文字定位“代码实际做了什么”时，可增加一张紧凑执行表：

```text
步骤 | 实际执行与判据 | 源码与产出映射
```

表后说明“完成”的含义及不能推出的结论。执行表不得新增未验证数字、伪造源码步骤或改变已冻结结果；若表格会造成分页、拥挤或重复，应改用一段短链和附录证据入口。

### 16.4 修改与验证闸门

- [ ] 输入、初始化/状态、循环/分支、停止/选择、输出和边界均能在真实证据中找到；
- [ ] 论文步骤与源码函数/模块/结果文件逐项可追溯，且没有把函数名当作数学解释；
- [ ] 验证单位与训练/拟合单位一致，目标标签没有反向进入选模或预处理；
- [ ] 确定性枚举没有被写成随机搜索、数值收敛或全局最优；随机算法的种子、重复运行和稳定性没有被省略；
- [ ] 求解器状态、可行性和最优性边界没有被“找到一个结果”替代；
- [ ] 公式、图表、冻结数字、标题和主张强度与改写前一致；
- [ ] 执行表在 PDF 中可读、无裁切、无跨页断裂，并没有挤压直接答案、验证或最终结论。

> 算法叙事的目标是让读者复现执行逻辑和判断边界，不是把论文改写成源码注释，也不是用算法名称替代证据。


## 17. 敏感性/稳健性证据的分层表达与边界闭环

### 17.1 “列出风险”不等于“证明稳健”

敏感性或稳健性结论至少要闭合：

```text
扰动对象
→ 扰动范围或替代口径
→ 响应指标
→ 稳定性判据
→ 失败边界或重算触发
```

“模型较稳定”必须改写为可检查对象，例如事件定位、排名、方向、点预测、参数、可行方案或最终决策在何种范围内保持什么性质。没有扰动范围、响应指标和判据时，只能写“风险已识别”，不能升级为稳健性结论。

### 17.2 三种证据状态必须分开

- `已量化敏感性`：已有真实扰动/替代口径及响应数值，可报告范围、方向或决策是否改变；
- `已识别但未量化风险`：知道风险来源和受影响主张，但尚无可信变化幅度；正文须说明风险、失效范围和补证/重算动作；
- `未建立的敏感性`：尚未执行相应比较；直接写“未建立”，不得用邻近实验、训练残差或课程阈值代替。

内部候选比较、重采样或条件情景只支持对应口径内的判断，不自动证明外部验证、总体覆盖、因果效果或统一泛化精度。时间序列、重复测量和同一对象多次记录的扰动与验证仍须尊重时间或分组结构。

### 17.3 正文矩阵只在能压缩证据时使用

当至少三个材料性对象需要同时比较，且连续文字会使“扰动—响应—边界”难以定位时，可使用：

```text
对象 | 扰动/替代口径 | 响应指标与稳定性判断 | 未证明边界/重算触发
```

表体只放已冻结、可追溯的数字和口径；没有量化的项显式标为“已识别但未量化”或“未建立”。若仅有一个简单敏感性检查，用相邻两三句即可，不为丰富版面强制制表。表格视觉通过只证明可读，不证明模型已经稳健。

### 17.4 修改与验证闸门

- [ ] 每条“稳定/稳健”都能定位扰动对象、范围、响应指标和判据；
- [ ] 已量化、已识别未量化、未建立三种状态没有混写；
- [ ] 条件情景、内部候选一致或训练残差没有升级为因果、外部验证或总体覆盖；
- [ ] 重复测量、时间序列和分组数据没有采用破坏结构的随机行级扰动/验证；
- [ ] 改变定义、分母、折分、候选、参考分布或目标输入时，重算触发条件明确；
- [ ] 新增表达没有改变冻结数据、公式、图表、模型、结果或主张强度；
- [ ] 矩阵只在材料性对象足够多时使用，并在最终 PDF 中完整、可读、不跨页断裂。

> 敏感性表达的目标是让证据强度和失败边界一眼可见，不是用一张表制造“模型已被证明稳健”的印象。
## 18. 参数、阈值、超参数与情景旋钮的来源合同

### 18.1 先分角色，再写数值

论文中的数值设置不能因为都能写成“参数”就混为一类。每个会影响结果解释、验证或下游决策的材料性设置，至少完成：

```text
数值设置
→ 角色分类
→ 来源或估计方式
→ 选择或标定口径
→ 已完成的验证
→ 未证明的边界
→ 改变后是否重算
```

角色分类至少区分：`观测输入/元数据`、`训练折内估计量`、`拟合参数`、`固定操作性阈值`、`固定超参数`、`报告水平`、`情景旋钮`。固定不等于由数据估计，默认值不等于最优，出现在参数表中也不等于来源和验证已经成立。

### 18.2 来源、选择与验证不得互相代替

- 观测输入或元数据要写明读取位置、单位、版本和变化时的重算范围；它不是调参结果。
- 固定操作性阈值要写明是规则、题意、专家口径还是预先固定的分析选择；未比较替代阈值时不得写“最优阈值”。
- 拟合参数要说明由哪些数据、目标和损失估计；训练折内估计量不得利用验证折或未来信息。
- 固定超参数要说明固定理由和候选共用口径；若宣称“选出的超参数性能”，调参与性能评估必须采用匹配的无泄漏验证，材料性时使用嵌套验证或等价的独立选择—评估结构。
- 报告水平只定义展示口径；80%/95% 标签不能自动升级为已校准的总体覆盖率、置信水平或安全保证。
- 情景旋钮表示条件输入、偏好或规划强度；它不是估计出的因果效应、生理上限、可达性或训练保证。
- 参数来源表只证明“已登记”，不证明选择正确、模型稳健或结论可外推；验证证据和未证明边界仍需单独写清。

### 18.3 正文矩阵的使用门槛

若至少三个材料性设置角色需要跨问或跨模型核对，可用紧凑矩阵：

```text
对象与设置角色 | 来源/选择口径 | 已完成的核验 | 未证明边界/重算触发
```

若只有一两个设置，应紧跟公式、算法步骤或结果段局部解释，不为丰富版面强制制表。表格可以跨页，但必须重复表头、保持语义行完整且最终 PDF 可读；视觉通过只证明版面可读，不证明参数最优、区间校准或情景可达。

### 18.4 修改与验证闸门

- [ ] 每个材料性数值设置都已分类，且角色没有被“参数”一词吞并；
- [ ] 来源/估计方式、选择/标定口径、已完成验证和未证明边界彼此分开；
- [ ] 固定阈值没有被写成拟合参数或最优值，默认超参数没有被写成已调优；
- [ ] 若性能主张依赖超参数选择，选参与评估没有信息泄漏，并使用匹配的嵌套或独立验证；
- [ ] 报告水平没有被写成总体覆盖保证，情景旋钮没有被写成因果效应或可达性保证；
- [ ] 改变阈值、超参数、折分、权重、报告水平、参考分布或情景输入时，重算触发范围明确；
- [ ] 新增表达只重组冻结事实，没有补造调参、敏感性、校准、数据、公式或结果；
- [ ] 参数来源矩阵只在至少三个材料性角色需要核对时使用，并在最终 PDF 中表头可辨、语义行完整、无裁切或重叠。

> 参数来源合同的目标是让每个数值“是什么、从哪里来、验证到哪一步、还不能证明什么”一眼可查，而不是用一张参数表制造最优性或科学性的印象。

## 19. 材料性假设的诊断、违反后果与放宽路径合同

### 19.1 先分类，再决定是否写成假设

不要把论文前置部分出现的所有口径都叫作“模型假设”。先区分：

- `material_assumption`：若不成立会实质改变模型、验证或核心结论；
- `operational_definition`：坐标、索引、缺失规则、事件口径、单位或配对键等可复现定义；
- `validation_design`：分组/时间切分、留一、外部验证或重采样安排；
- `scenario_condition`：固定模型关系下改变的条件输入、偏好或规划强度。

单位、坐标、固定常数、验证设计和情景旋钮分别登记，不得为充实“模型假设”一节而包装成现实机制。拒绝“数据真实可靠”“误差可以忽略”等无法承担诊断与失效责任的通用套话。

### 19.2 每条材料性假设必须闭合后果

```text
材料性假设
→ 现实/数据来源或采用理由
→ 在模型中的作用
→ 受影响公式、验证与主张
→ 可检查信号或诊断
→ 违反后的结论降级
→ 放宽路径或替代模型
→ 重算范围
```

可检验性至少分为 `可直接检查`、`可间接诊断`、`当前数据不可检验`。诊断未拒绝或暂未出现反例，不等于假设已被证明；不可检验的假设必须降低主张强度，并说明需要什么新增数据、标定、实验或替代模型。

### 19.3 违反假设必须改变交付

违反信号不能只进入“局限性”段。它至少应导致以下一种动作：缩小适用域、降低因果/外推/精度主张、扩大不确定性、撤销情景建议、把主模型降为基线、改用更宽松的结构，或解冻并重算受影响问题。若假设变化但论文数字和结论完全不变，说明其可能不是材料性假设，或重算范围尚未识别。

### 19.4 正文矩阵的使用门槛

至少三条材料性假设需要跨问核对时，可用紧凑矩阵：

```text
材料性假设及其作用 | 当前依据/可检查信号 | 违反后的结论降级 | 放宽路径/重算范围
```

操作性定义、验证设计或情景条件若与假设同表，必须显式标类，不能暗示它们已获现实验证。若只有一两条假设，紧跟对应公式、结果或验证段局部解释；不为增加表格数强制制表。矩阵视觉通过只证明可读，不证明假设成立或模型正确。

### 19.5 修改与验证闸门

- [ ] 假设、操作性定义、验证设计和情景条件没有混类；
- [ ] 每条材料性假设说明采用理由、模型作用和受影响主张；
- [ ] 可检查状态标明为可直接检查、可间接诊断或当前数据不可检验；
- [ ] “未拒绝/未见反例”没有写成“已经证明成立”；
- [ ] 违反后明确降低结论、改变交付或触发回退，而不是只加免责声明；
- [ ] 放宽路径对应新增数据、标定、替代结构或验证，并给出解冻重算范围；
- [ ] 新增表达没有补造敏感性、实验、校准、因果关系、公式、数据或结果；
- [ ] 矩阵只在至少三条材料性假设需要核对时使用，并在最终 PDF 中语义行完整、无裁切、重叠或乱码。

> 假设合同的目标不是让论文看起来更严谨，而是让评委知道模型依赖什么、当前怎样诊断风险、失效时哪些结论必须撤回，以及下一步如何放宽并重算。

## 20. 结论的证据等级、动词强度与行动权限合同

### 20.1 结论动词不是修辞选择

结论中的动词决定读者可以采取什么行动。先为每条材料性结论识别证据等级，再限制允许动词和下游行动：

```text
结论对象
→ 结论层级
→ 直接证据载体
→ 验证范围
→ 允许动词
→ 禁止升级动词
→ 允许行动
→ 人工拍板或新增证据闸门
→ 失效/重算触发
```

不得因为数字可复算、算法常用、软件计算精确或某项内部检验通过，就把结论升级为现实准确、因果有效、总体泛化、现实最优或正式决策。

### 20.2 六级结论与动作边界

1. `direct_measurement_or_computation`：在已声明定义、单位和精度下使用“计算得到、检测到、在本口径下为”；不自动称为人工真值、真实值或精确测量。
2. `descriptive_or_associational_finding`：使用“观察到、相关、表现为、可作为关注线索”；不得写“导致、改善、训练有效、机制已证明”。
3. `internally_validated_conditional_prediction`：使用“在当前模型/同来源匹配验证下预测或估计”；不得写“将达到、保证准确、总体泛化、适用于任意新个体”。
4. `scenario_or_planning_reference`：使用“在预设情景下模型给出、情景值、规划参考”；不得写“训练反应、可达上限、承诺值、必然结果”。
5. `operational_recommendation_with_guardrails`：只有证据、可行性、风险和复测/拒绝/停止条件齐全时，才写“可优先复测、可作为候选方案、满足条件时采用”；不得直接写“应实施、最优方案、正式决策、安全性已验证”。
6. `formal_decision_or_deployment`：必须由责任人人工批准；后果重大时还需要外部、现场或时间外验证。AI 不得自行把模型输出提升到本级。

### 20.3 结论段的最小写法

逐问结论至少包含：冻结答案、证据/验证范围、允许行动和禁止升级。只有一两条存在越权风险时，用相邻短句修正；至少三种材料性结论等级需要跨问核对，且矩阵能压缩而非增加负担时，才使用：

```text
对象 | 证据等级与载体 | 允许动词/行动 | 禁止升级与人工闸门
```

不要为显得严谨强制新增表格。结论不新增正文未证明的方法、数字或贡献，也不能用“通过检验”“结果合理”统摄不同范围的证据。

### 20.4 不可跨越的边界

```text
结论能被复算 ≠ 行动已经被验证
模型内部最优 ≠ 现实最优
安全规则被写出 ≠ 安全性已得到验证
条件推荐 ≠ 正式决策
```

### 20.5 修改与验证闸门

- [ ] 每项直接答案已分为直接计算、观察/关联、内部条件预测、情景规划、带护栏推荐或正式决策；
- [ ] 允许动词与直接证据、验证对象和适用域匹配；
- [ ] 因果、总体泛化、可达性、安全、最优性或承诺没有从较低证据等级升级；
- [ ] 每条建议写清允许行动以及复测、拒绝、停止或人工拍板点；
- [ ] 数字、单位、分母、公式、图表、引用和冻结结果均未改变；
- [ ] 只修正语义权限，没有补造实验、外部验证、训练反应或部署证据；
- [ ] 结论矩阵只在至少三种材料性等级需要比较且能减少认知负担时使用；
- [ ] DOCX/PDF 重建后无页数失控、裁切、重叠、乱码或尾部章节冲突。

> 证据等级限制动词，动词限制行动。语言变强必须以新增相称证据和责任人人工拍板为前提。
## 21. 数值显示精度、证据分辨率与决策阈值合同

### 21.1 显示位数必须有证据依据

机器精度不等于测量精度。正文、表格和图注的显示位数应按测量/采样分辨率、验证误差尺度或其他已建立的不确定性尺度，以及决策用途共同确定；输入表有两位小数不等于外推预测具有两位现实精度，跨位置小数位一致也不等于显示精度有证据支持。图示读数、帧级事件、离散网格或有限搜索结果不得报告超过采样、网格或容差分辨率所支持的现实精度。

最低登记链为：

```text
对象
→ 底层未舍入冻结值
→ 数据/测量或采样分辨率
→ 验证误差或不确定性尺度
→ 决策用途、阈值或排序间隔
→ 允许显示精度
→ 舍入临界保护规则
→ 重算触发
```

只有多个材料性数值对象需要跨问或跨载体核对，且制表能减少负担时才建立精度登记表；普通情形使用相邻短句或结果登记字段，不为形式完整强制新增论文表格。

### 21.2 决策始终使用未舍入冻结值

模型选择、排序、阈值、可行性和停止/拒绝判断必须使用未舍入冻结值，不得从摘要、表格或图注中的舍入文本回算。若舍入可能造成并列、反转或跨阈值，应保留保护位或显式报告临界状态；显示精度可以改变，但底层冻结计算值、模型入选、阈值状态和行动边界不得因此改变。

### 21.3 修改与验证闸门

- [ ] 每项材料性数字已区分底层未舍入冻结值与论文显示值；
- [ ] 显示位数与测量/采样分辨率、验证误差或不确定性尺度和决策用途相称；
- [ ] 机器输出位数、输入小数位或跨位置格式一致没有被当作现实精度证据；
- [ ] 排名、阈值、可行性、停止/拒绝和模型选择均使用未舍入冻结值；
- [ ] 可能并列、反转或跨阈值的对象已保留保护位或标为临界状态；
- [ ] 图示读数、帧级事件、离散网格/搜索没有超过采样、网格或容差分辨率；
- [ ] 改变分辨率、误差尺度、容差、阈值或排序规则时，已解冻并重新审计或重算受影响结果；
- [ ] 仅改变显示精度时，已回放摘要、正文、表格、图注和结论，且底层冻结值与语义不变。

> 本合同约束“显示多少位”和“用什么值做判断”，不新增测量能力、不确定性估计、外部验证或决策证据。

## 22. 关键推导的材料性步骤与正文停点合同

### 22.1 先判断步骤是否改变模型语义

关键推导不是公式越多越好。按下列四类处理：

1. **A 类：语义改变步骤，正文保留。** 凡改变分母、权重、方向、单位、索引/数据层级、损失/约束、变量域、模型选择、结果或决策的转换，均属于材料性步骤；必须说明起点、转换理由和输出去向。
2. **B 类：实现接口，可紧缩。** 数据输入、预处理、求解器调用和输出写回若不改变模型定义，可压缩为“输入—处理—输出—复核入口”，但不能用“使用 MATLAB 计算”或“经程序求得”跨过模型语义步骤。
3. **C 类：标准证明或机械代数，可下沉。** 教材级证明、逐行矩阵求导、正规方程的机械展开和库内部步骤可放入附录、代码或省略，前提是正文已足以恢复可计算式。
4. **D 类：无下游用途，删除。** 不连接结果、验证、选择或决策的公式和推导，不因“显得充实”而保留。

### 22.2 正文停点

最低闭环为：

```text
起点量/现实关系
→ 材料性步骤
→ 可计算式
→ 冻结结果或选择
→ 复核入口
```

同时满足以下条件即达到正文停点：读者能从已声明输入恢复可计算式；所有材料性转换已经出现；省略部分不改变模型语义且能从附录、代码或结果文件复核；公式已经连接冻结结果、模型选择或验证。达到停点后停止扩写，不继续复制教材证明、机械代数、逐行代码或无用途公式。

### 22.3 修改与验证闸门

- [ ] 分母、权重、方向、单位、索引/数据层级、损失/约束和变量域的变化均未被跳过；
- [ ] 候选比较、模型选择、结果尺度和决策口径能沿推导链恢复；
- [ ] “使用软件计算/经程序求得”没有替代材料性步骤；
- [ ] 正文已给出可计算式、冻结结果/选择和复核入口；
- [ ] 教材证明、机械代数和库内部步骤仅在不改变模型语义时下沉；
- [ ] 已达到正文停点的段落不为增加公式数或页数继续扩写；
- [ ] 新增表达没有补造公式、数据、结果、验证、因果、外推或最优性证据。

> 正文应保留改变答案含义的桥，省略不改变答案含义的机械过程；“充实”来自证据闭环，而不是推导长度。


## 23. 图表证据编码真实性、离散节点与非颜色冗余合同

### 23.1 图形本体必须与证据状态一致

图注和正文中的限制不能修复图形本体的过度编码。每张材料性图先闭合：

```text
主张与数据对象
→ 观测/汇总统计/模型输出/条件情景
→ 标记类型与连接关系
→ 坐标尺度、基线和单位
→ 不确定性/缺失/排除定义
→ 阈值、基线或选择标记
→ 非颜色冗余
→ 图中可见判断
→ 不能推出的更强结论
```

不得把原始观测、汇总量、拟合输出和条件情景画成无法区分的同一类标记。柱形、面积等以长度或面积编码大小时通常从零基线起；点线图使用非零轴可以成立，但必须保留足够上下文，断轴须显式披露。双轴容易制造相关性，优先拆成共享横轴或对齐面板。缺失、零值、删失和排除必须可区分，不得静默跨缺失连接。

### 23.2 只有有限节点时，不得包装成完整连续响应

若代码只计算了有限枚举点、离散候选或登记情景，图中应让节点身份可见。连接线如仅用于阅读顺序，使用弱化虚线或其他辅助样式，并在图注中明确“仅连接已计算节点，不表示节点之间的完整响应函数”。只有变量具有天然顺序且相邻区间确已计算、插值规则已定义或连续函数本身就是模型对象时，才能把实线曲线解释为连续响应。

```text
已计算四个情景节点 ≠ 已验证全区间响应曲线
节点单调 ≠ 全区间单调
模型情景 ≠ 已观测训练效果
视觉延续 ≠ 预测准确性证据
```

### 23.3 颜色不能是唯一材料性通道

类别、阈值、选择点、基线、观测/预测来源和方案状态等会影响判断的对象，至少再使用一种线型、marker、轮廓、填充、直接标签或分面进行冗余编码。冗余不是增加装饰：不承担主张的个体身份无需强行多色；系列过多时优先拆图或删除无关系列。最终彩色图还须查看灰度或等价的非颜色预览，但灰度可辨不等于已经证明无障碍或科学正确。

### 23.4 不确定性与参考线必须命名真实职责

误差条、带状区、阴影、阈值线和基线线必须说明它们是 SD、SE、CI、经验分位带、容差、模型情景、决策阈值还是比较基线，并写明重复单位或构造口径。选择基线不能称为置信线，经验误差带不能称为总体覆盖保证；没有相应估计时不得为“丰富图表”补造区间。

### 23.5 修改与验证闸门

- [ ] 图形标记已区分原始观测、汇总统计、模型输出和条件情景；
- [ ] 柱形/面积的零基线、点线图的非零轴、断轴、对数轴和双轴均有诚实理由与披露；
- [ ] 缺失、零、删失和排除可区分，未静默跨缺失连线；
- [ ] 只有有限登记节点时，未用连续实线暗示未计算的完整响应函数；
- [ ] 材料性类别、阈值、基线和选择点具有非颜色冗余，灰度或等价预览已实际检查；
- [ ] 区间、误差带、阈值线和基线线的统计/决策职责已命名；
- [ ] 改图前后底层数据、节点、顺序、单位、冻结结果和正文主张保持一致，除非本轮明确解冻重算；
- [ ] 图注说明图中可见事实和禁止推出的结论，不用文字掩盖图形本体的误导；
- [ ] 最终 DOCX/PDF 中坐标、图例、直接标签和图注在实际缩放下可读，无裁切、遮挡或页数失控；
- [ ] 没有为了图表数量、色彩或“论文丰富”增加重复图、虚假区间或无主张系列。

> 图表丰富度来自证据角色完整，而不是曲线、颜色或面板数量。图形只能编码已经计算且能够复核的对象。

## 24. 证据载体稳定编号、首次引用与跨页导航合同

### 24.1 编号是证据地址，不是版面装饰

材料性公式、表、图、附录和代码入口应具有稳定、唯一、可搜索的身份，使评委、队员和复核脚本能够从主张回到证据，也能在重新分页后恢复定位。最低导航链为：

```text
为什么现在看该载体
→ 稳定编号/标签
→ 载体对象与口径
→ 它支撑的判断
→ 下一证据或复核入口
→ 不能推出的边界
```

首次引用必须说明用途，不能只写“如图 3 所示”；结果段应按编号回指决定性证据。不得用“下表、上图、如下、前表、后图、表中结果、本表”等位置词承担唯一定位，因为导出、插图和跨页后这些词可能失效。稳定编号只解决证据可寻址性，不证明模型正确、结果真实、创新成立或获奖。

### 24.2 只编号材料性载体

采用选择性编号：直接支撑答案、模型选择、验证、边界、决策或复现的载体必须编号；纯导航、版面辅助或一次性前置信息不为追求形式完整机械编号。前置符号表、数据审计表可不编号，但必须明确写成“前置表，不编号”或等价角色，避免正文出现无法解释的编号断裂。不得让正文从表 3 起跳却无法说明表 1、表 2 的去向，也不得因局部标题或 Markdown alt 已含编号而在最终 PDF 生成“图 1：图 1……”这类重复图号。

若论文使用 LaTeX 标签、Word 题注或 Markdown 转换，编号来源应保持单一；正文引用、题注、目录/交叉引用和最终 PDF 的显示身份必须一致。附录和代码入口除编号外还应提供文件名、模块/函数或结果 ID 等可搜索信息，不用页码作为唯一复现入口。

### 24.3 首次引用、载体邻接与跨页规则

- 首次引用先写本载体用于核对、比较、诊断或支持什么，再出现编号；空壳“如图所示”不构成用途说明。
- 表题应与表头和首行同页；图注应与对应图合法邻接，不能跨页后与其他图混淆。
- 跨页表重复表头，并尽量保持语义行完整；拆表时保留续表身份和相同口径。
- 重新排序、插入或删除载体后，重查编号连续性、正文回指、附录/代码入口和页码导航。
- 最终 PDF 搜索编号并逐页查看，确认没有孤立表题、断裂图注、重复图号、错误回指或只靠位置词定位。
- 不为恢复固定页数而缩小到不可读字号、使用违规边距、压坏载体邻接或删除验证证据；真实分页代价应登记并由版面/内容优先级共同裁决。

### 24.4 比赛期间路径

**6 小时压缩路径：**只给每问核心结果表/图和直接影响决策的材料性载体编号；首次引用写一句目的；结果段按编号回指；导出后搜索编号连续性、重复图号和位置词残留。前置符号表或数据审计表允许不编号，但须标明角色。

**12—18 小时完整路径：**补齐材料性公式、表、图、附录和代码入口的双向导航；登记“载体—主张—result ID—页码/复核入口”；每次重排后重建交叉引用，并逐页检查表题/图注邻接、跨页表表头和编号恢复性。

### 24.5 修改与验证闸门

- [ ] 材料性公式、表、图、附录和代码入口具有稳定、唯一、可搜索身份；
- [ ] 选择性编号口径可解释，前置不编号表的角色明确，不存在编号断裂；
- [ ] 首次引用写清用途，结果段按编号回指，而非只写“下表、上图、本表”；
- [ ] 题注编号来源单一，最终 PDF 不出现“图 1：图 1……”或其他重复图号；
- [ ] 表题与表头和首行同页，图注与图合法邻接，跨页表重复表头；
- [ ] 插删、重排和分页变化后重新检查编号、引用、附录/代码入口与逐页视觉；
- [ ] 没有为压回固定页数牺牲可读性、规则、验证证据或真实边界；
- [ ] 稳定编号未被写成模型正确、结果真实、创新成立或获奖证据。

> 证据载体只有能被稳定找到、知道为何查看并能继续复核，才真正进入论文论证链。


## 25. 图内主语言、术语与多面板身份一致性合同

### 25.1 图形本体也属于论文叙事

中文论文中的材料性图形原则上采用与正文一致的主语言，使总标题、面板标题、坐标轴、图例、直接标签和图注能够沿同一术语链恢复。单位、变量、模型专名以及 `MAE`、`RMSE` 等通用缩写可以保留，但必须与正文术语一一对应；“全部翻译成中文”不是目标，减少未定义的中英切换才是目标。

最低术语链为：

```text
正文对象与主张
→ 图内同义术语/必要缩写
→ 轴标题与单位
→ 图例或直接标签
→ 图注中的展示对象与面板职责
→ 正文按稳定身份回指
→ 不能推出的边界
```

同一对象不得在正文、图内、图注之间交替使用未定义的近义词，例如把同一预测量混写成 `score`、`distance`、`result`，或把同一分析单位混写成 `athlete`、`player`、运动者。翻译和术语统一不得改变数据、比例尺、轴范围、方向、单位、阈值、节点、曲线、模型输出或结论。

### 25.2 多面板图使用稳定身份

当多面板图的各面板承担不同主张、会被正文单独引用、可能拆分/重排，或需要跨页后恢复定位时，使用稳定的 `(a)(b)…` 或独立图号。面板标题、图注和正文回指使用同一身份；不得只靠“左图、右图、左上、其他面板”等位置词承担唯一定位。位置说明可作辅助，但不能替代稳定身份。

图注至少说明各材料性面板展示什么、共享什么口径，以及哪一面板支撑哪一判断；正文只回指真正需要单独解释的面板，不为形式完整机械罗列所有字母。稳定面板身份提高的是可寻址性，不证明图形正确、模型有效、结果真实或创新成立。

### 25.3 来源未解释的图内字符不得擅自赋义

源图、视频帧、地图、仪器截图或外部底图中若存在来源未登记的数字、文字、图标或叠加标记，应先追踪其来源和语义。无法核实时，要么在不破坏证据本体的前提下遮蔽/裁除并登记处理，要么保留并明确声明其不承担的证据角色；不得猜测它是对象编号、试次、分数、状态、时间或事件标签。来源未解释字符的存在也不得被用作额外结果或验证。

### 25.4 比赛期间路径

**6 小时压缩路径：**材料性图至少统一总标题、轴标题、图例和正文中的核心术语；承担不同判断的面板加 `(a)(b)…`；图注按面板身份说明职责；扫查来源未解释字符并登记“已核实/已移除/保留但不作证据”。单位与通用缩写不强制翻译。

**12—18 小时完整路径：**建立“正文术语—图内术语/缩写—面板身份—单位—图注职责—主张”对照；重绘后比较冻结输入、数据/节点、画布和科学数字；重建最终 DOCX/PDF，逐页检查实际尺寸下的中文字体、术语拥挤、面板身份和图注回指。

### 25.5 修改与验证闸门

- [ ] 中文正文的材料性图形采用一致主语言，保留的单位、变量、专名和通用缩写与正文一一对应；
- [ ] 面板标题、轴标题、图例、直接标签和图注对同一对象使用同一术语；
- [ ] 承担不同主张或需单独引用的面板具有稳定 `(a)(b)…` 或独立图号，正文和图注不用位置词唯一定位；
- [ ] 来源未解释的图内字符已追踪；不能核实时未擅自赋义，并已明确不承担的证据角色或登记移除处理；
- [ ] 翻译、术语统一和面板编号前后，冻结输入、数据、几何编码、比例尺、轴范围、单位、阈值、节点、曲线、模型输出和科学结论未改变；
- [ ] 最终 DOCX/PDF 中中文无缺字或方框，面板身份、轴标题、图例和图注在实际尺寸下可读，无裁切、遮挡、拥挤或异常分页；
- [ ] 语言一致和面板身份没有被写成模型正确、结果真实、创新成立或获奖证据。

> 图内语言与面板身份的目标，是减少评委在正文—图注—图形之间的翻译和位置恢复成本；它不能替代数据、模型、验证和结论边界。


## 26. 最终物理尺寸、信息密度与局部可读性合同

### 26.1 先按最终载体设计，而不是先画大图再缩印

材料性图形在绘制前先确定最终 PDF/DOCX 中的目标嵌入宽度、栏宽、页面方向和允许图高，再据此设置画布、面板数、标签方向和字号层级。Matplotlib 源字号、源画布英寸或 DPI 都不等于最终可读性证明；大画布上的文字在缩入正文后会随线性尺度一并缩小。

可用下式做风险筛查：

```text
最终有效字号 ≈ 源字号 × 最终嵌入宽度 / 源原生物理宽度
```

该估算只用于识别可能过小的标签、刻度、图例和注释，不是脱离模板、介质、字体与阅读设备的固定合格线。不得据此制定普遍的 6 pt、8 pt 等单一门槛；最终裁决仍来自生成后的实际 PDF/DOCX。

### 26.2 拥挤时先降低非材料性密度，不先继续缩小字号

图内信息拥挤时按以下顺序处理：

```text
删除不承担主张的系列或装饰
→ 缩短标签并登记正文—图内术语映射
→ 使用直接标签减少图例往返
→ 改变方向、分面或面板结构
→ 拆图，或把非核心明细移入附录
```

只有在最终载体中仍可稳定辨认、且不破坏全文字号层级时，才允许小幅调整字号。不得用继续缩小文字、压扁画布、删除单位/边界或堆叠图例来换取同页。PPI/DPI 只描述栅格采样，不证明文字可读、科学编码真实、模型正确或主张成立。

### 26.3 可读性 A/B 必须保持科学不变量

若仅验证版式或局部可读性，A/B 前后必须保持底层数据、样本/节点、排序、轴域、单位、阈值、基线、模型输出、冻结数字和正文主张不变；改变图方向、标签位置或面板布局不能偷偷改变比较口径。若确需改变任一科学对象，应解冻结果并重新进入计算与验证流程，不得把它包装成纯表达修改。

### 26.4 最终载体的三层视觉裁决

导出后必须同时检查：

1. **整页**：在页面上下文中检查信息层级、图文比例、空白、裁切、重叠和是否能找到主证据；
2. **局部**：按 100% 或实际阅读比例检查轴标题、刻度、类别、图例、直接标签、注释、线型/marker 和关键数字；
3. **邻接与下游分页**：检查图与图注、图前/图后正文是否相邻，后续章节、表图和页数是否发生未审计漂移。

局部可读性优化若造成页数增长、图注分离、后续章节起始漂移或其他核心证据被压缩，视为当前版本未闭环；应恢复最终图框比例、重新布局或拆图后再次构建和逐页检查。源图可读、编辑器预览正常或 PPI 足够，都不能替代最终 PDF/DOCX 的整页与局部视觉裁决。

### 26.5 比赛期间路径与验证闸门

**6 小时压缩路径：**先按最终栏宽/页宽设置核心图画布；只保留承担主张的系列；类别拥挤时优先直接标签、改变方向或拆图；导出后至少检查核心图所在整页、100% 局部和下一页是否漂移。

**12—18 小时完整路径：**登记“最终嵌入宽度—源原生物理宽度—缩放筛查—拥挤处置—A/B 科学不变量—最终整页/局部—下游分页”；对修改图重建全文并逐页复核，保留失败版与恢复理由。

- [ ] 绘图前已确定最终嵌入宽度、页面/栏宽和允许图高；
- [ ] 未把源字号、源画布英寸、DPI/PPI 当作最终可读性证明；
- [ ] 缩放估算只用于风险筛查，未写成脱离载体的固定 pt 合格线；
- [ ] 拥挤时先删除非材料性系列、缩短且登记术语、直接标签、改变方向/分面、拆图或移附录，未首先继续缩小字号；
- [ ] A/B 前后数据、排序、轴域、单位、阈值、模型输出、冻结数字和主张保持一致，或已明确解冻重算；
- [ ] 最终载体已检查整页、100% 或实际阅读比例局部，以及图注/正文邻接；
- [ ] 页数、图注分离和下游分页已经复核，局部改进未制造未审计的全文漂移；
- [ ] PPI 足够未被写成文字可读、科学正确、模型有效或获奖证据。

> 最终可读性属于论文载体中的证据可达性：先按最终尺寸设计，再用缩放筛查风险，最后以实际导出物的整页、局部与分页检查裁决。
## 27. 上游选择对象与下游诊断面板的身份交接合同

### 27.1 触发条件与最小闭环

仅当同一多面板图满足以下结构时启用本合同：上游面板从多个候选模型、方案或对象中选出一个，下游面板只诊断该入选对象。此时评委不应依赖颜色、面板邻接或短时记忆猜测诊断对象：

- 上游选择面板必须用非颜色、可打印的显式标记指出入选状态，例如轮廓、线型、纹理、marker、直接标签或等价编码；
- 下游诊断面板的标题、直接标签或等价图内文本必须重复入选对象身份；
- 图内、图注和正文使用同一稳定对象术语，正文按面板身份说明“选择什么”和“诊断什么”；
- 入选对象必须来自冻结的模型选择或决策结果，绘图脚本只读取并表达，不得临时重算、重新排序或重新拍板；
- 若多个下游面板分别诊断不同对象，每个面板都必须给出自身的稳定对象身份。

这不是对所有多面板图增加箭头、固定标题句式或冗长图内文字的要求。若面板共享同一对象、没有选择—诊断交接，或对象身份已经无需跨面板恢复，不应机械增加标记。新增文字和编码仍须通过第 26 节的最终尺寸与局部可读性检查。

### 27.2 表达 A/B 与证据边界

只验证身份交接表达时，A/B 必须保持数据、候选顺序、轴域、单位、阈值、基线、冻结选择结果、模型输出和正文主张不变；若任一对象改变，应解冻并回到计算、选择与验证流程。对象身份闭合只证明读者能恢复“哪个对象被选中、哪个对象正在被诊断”，不证明模型选择正确、唯一最优、外推有效或结论真实。

### 27.3 比赛期间路径与检查表

**6 小时压缩路径：**对“候选比较→入选对象诊断”图，只做三项检查：冻结结果中的入选对象与图一致；上游有一个非颜色入选标记；下游标题或直接标签重复对象身份。随后在最终 PDF/DOCX 中检查一次整页和局部可读性。

**12—18 小时完整路径：**登记“冻结选择结果→上游入选编码→下游对象命名→图注/正文同名回指→A/B 科学不变量→最终载体复核”，并检查多个下游面板是否分别闭合对象身份。

- [ ] 上游面板的入选状态具有非颜色、可打印的显式标记；
- [ ] 下游面板重复入选对象身份，不得只靠颜色、面板邻接或读者记忆；
- [ ] 入选对象来自冻结结果，绘图脚本没有临时重判；
- [ ] 图内、图注和正文使用同一对象术语；
- [ ] A/B 的数据、排序、轴域、单位、选择结果和主张保持不变，或已明确解冻重算；
- [ ] 新增标记未破坏最终尺寸可读性、图注邻接或下游分页；
- [ ] 身份交接清楚未被写成模型选择正确或唯一最优的证据。

> 该合同减少的是选择面板到诊断面板之间的对象恢复成本；它不能替代模型选择、验证和结论边界。
