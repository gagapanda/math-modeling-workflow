# Evidence-Driven Math Modeling Workflow

面向数学建模竞赛的 AI 工作流：从题目拆解、数据审计和模型验证，一直延伸到论文、合规检查与提交包核验。

本仓库最适合交给**能够读取整个工作区并执行本地命令的编码型 AI** 使用。它不是一个自动获奖器，也不会用机器检查代替数学正确性、官方规则或人工最终确认。

## 下载后怎么交给 AI

1. 下载或克隆整个仓库，不要只下载 `SKILL.md`。
2. 在支持工作区文件与终端的 AI 工具中打开仓库根目录。
3. 把题目、附件和已有成果放进仓库外的独立案例目录，或先用下面的命令生成案例骨架。
4. 将这段提示词发给 AI，并替换方括号内容：

```text
请把当前仓库作为数学建模工作流使用。先阅读
.agents/skills/math-modeling/SKILL.md，再根据任务只读取必要的 references，
不要一次加载全部文档。

任务模式：[学习 / 历史题练习 / 正式比赛 / 论文审阅]
题目与附件：[路径]
已有代码、结果或论文：[路径；没有则写“无”]

请先检查材料、当前状态和缺失信息，说明采用的工作流入口与下一步，
然后直接开展工作。正式比赛必须重新核对当届官方规则并持续记录 AI 使用；
不得把脚本 PASS 当作模型正确、人工验收或正式提交完成。
```

如果使用的是只能接收聊天附件、不能访问文件系统或终端的普通对话 AI，它可以阅读部分材料并给建议，但无法完整运行本仓库的脚本、复现实验或验证提交包。这种方式不等同于启用完整工作流。

## 三分钟开始

要求：Git、Python 3，以及能够运行本地命令的 AI 工具。Windows 提供了统一的 PowerShell 入口；其他系统可以直接调用对应的 Python 脚本。

```powershell
git clone https://github.com/gagapanda/math-modeling-workflow.git
cd math-modeling-workflow

# 查看入口
.\mm.ps1 --help

# 创建一个历史题练习案例
.\mm.ps1 start demo-case --root .\work --profile practice --json
```

随后把题目和附件放入 `work/demo-case/problem/`，在 AI 工具中发送上面的提示词，并将题目路径写为 `work/demo-case/problem/`。

### 工作模式

| 模式 | 用途 | 入口参数 |
|---|---|---|
| 探索 | 题目拆解、数据检查、模型路线比较 | `--profile explore` |
| 练习 | 可复现求解、验证、论文与普通质量门 | `--profile practice` |
| 正式比赛 | 在练习流程上增加当届规则、匿名、AI 披露和提交证据 | `--profile submission` |

不要为了获得更严格的报告而把练习伪装成正式提交。正式比赛模式仍需要参赛者亲自确认官方规则、人工审核和实际上传结果。

## 核心优势

- **全链路可追溯**：题目定义、数据处理、模型、代码、结果、图表和论文结论沿同一证据链组织，关键产物可用路径与 SHA-256 绑定。
- **不靠文件名猜最终版**：结果、论文和支持包候选分别登记；当前版本、被替代版本和人工选择都有明确状态。
- **先验证再包装**：从透明基线开始，根据时间、分组、空间或重复测量结构选择验证方式，并保留泄漏、稳定性、敏感性和适用边界检查。
- **论文不是计算后的附属品**：结果 ID、公式、图表、正文回答和限制说明可以交叉核验，最终 PDF 仍要求逐页检查。
- **技术完成与正式提交分离**：结果冻结、论文权威、规则与 AI 合规、本地提交包验收、官方上传和回执分别记录，机器检查不能冒充人工签字。
- **经验可以持续回流**：比赛和训练中的有效做法、失败原因与修复措施经过证据审查后，才能进入模板、脚本、测试或质量门，避免把一次性经验直接当成通用规则。

这些优势提高的是正确性、稳定性、可复现性和交付质量，不构成获奖、模型有效性或官方验收保证。

## 常用入口

```powershell
# 查看案例状态，不修改案例
.\mm.ps1 status --case-dir .\work\demo-case --json

# 汇总基础检查
.\mm.ps1 check --case-dir .\work\demo-case --json

# 查看候选稿管理命令
.\mm.ps1 candidate --help
```

`mm` 是薄封装入口，负责把常见操作转交给底层工具。结果冻结、合规确认、最终包验收和官方上传仍分别保留自己的证据与人工权限边界。

## 它能协助什么

- 将每个问题拆成目标、输入、输出、约束、假设和验证标准；
- 审计数据，保留来源、清洗变更和结果之间的可追溯关系；
- 从透明基线开始选择模型，并用与主张相匹配的方式验证；
- 管理结果、论文和支持包候选，避免依赖文件名或修改时间判断最新版；
- 对接代码、数字、图表、正文和结论，检查论文中的证据链；
- 检查匿名、引用、AI 使用记录、文件清单和提交包一致性；
- 将赛后发现分类为采用、延期、拒绝或仅限案例，再沉淀为可复用改进。

## 它不能替你保证什么

- 模型一定正确、结论一定有效或比赛一定获奖；
- 历史规则在下一届比赛仍然有效；
- AI 输出已经经过真实的人类复核；
- 本地打包成功等于已经上传，或等于平台已经出具回执；
- 私有案例、课程资料、优秀论文、下载的 LaTeX 模板和字体已经包含在公开版中。

Word/PDF 是可选后端，可能需要额外的文档环境。开始论文导出前请阅读 [导出与页面检查](docs/paper-export.md)。公开版的完整能力边界见 [迁移状态](docs/migration-status.md)。

## 工作流核心

所有正式结论都应沿着同一条链路回溯：

```text
problem -> assumptions -> data -> model -> algorithm
        -> result -> validation -> conclusion
```

仓库把技术完成、论文完成、合规通过、人工确认和正式上传分开记录。脚本只证明它实际检查过的内容，不会自动签署人工关口。

## 目录

- `.agents/skills/math-modeling/`：主 Skill、脚本、Schema、模板和回归测试；
- `docs/`：使用边界、导出说明、迁移状态和发布来源；
- `examples/`：经过许可或自造的最小示例；
- `templates/`：通用登记和检查模板；
- `scripts/`、`tests/`：公开版本身的发布检查。

AI 的主入口是 [.agents/skills/math-modeling/SKILL.md](.agents/skills/math-modeling/SKILL.md)。它会根据任务选择必要参考，不应一次性加载全部资料。
