## 用户授权依据（C4）

- 项目发起人先明确确认最初的 math-modeling Skill 是其委托 Codex 从零创建的。
- 在被明确询问是否接受他人商业使用、修改并用于收费产品/服务后，用户回答：“完全开源全部接受”。
- 本次据此选择符合该开放意愿的 MIT，并将许可落实到经过 B/C/C1/C2 筛查与 C3 来源复核的项目候选集合，而非私人工作区全部内容。
- 用户授权和初始来源陈述是记录依据，不是独立原创性、作者身份、所有后续代码权利或 AI 输出版权地位的法律鉴定。没有将未知第三方内容重新授予 MIT。

机器清单中的 `authorization_status: confirmed` 在本次表示“用户已授权以本项目许可证分发已审查的项目内容”；它不是对法律权利的独立证明。每条记录绑定本节授权依据及原有来源批次。原先的 `NOASSERTION / pending_owner_review` 是选择许可前的历史状态，不代表发现了逐文件侵权。

## 检查入口与含义

```powershell
python -B scripts/check_release_inventory.py
python -B scripts/check_release_inventory.py --require-release
```

当前两条入口均应通过：前者检查覆盖/哈希/声明，后者追加项目及逐文件许可声明检查。`release_ready: true` **仅是本脚本的来源清单/许可声明检查通过**，不是代码正确性、秘密/历史扫描、完整依赖 SBOM、漏洞、法律权利或实际远程发布的批准。不得因该字段就自动提交或推送。

清单自身 sha256:null 避免递归哈希；其余记录绑定当前文件字节。后续有修改须重新审查及更新清单，新增或未知来源文件不能自动继承 confirmed。`.git`、`.venv`、`local-work`、`__pycache__` 和生成的 toy-figure.png 被排除不等于可以分发。不要整体上传私人目录或直接把未核对的工作树打包。
